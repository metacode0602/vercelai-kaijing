## 0. 结论先行

1. 当前落地页与仓库产品**完全不匹配**：文案、导航、CTA、定价和图片都是 GPURun GPU 云/Agent 沙盒，且存在 `/console/sandbox`、`/bare-metal`、`/models` 等失效或不对应入口。
2. 新叙事不把 Open Shop 包装成「又一个功能更多的 ERP」，而是：
   > **ERP 管事实与审批，Desktop 管 AI 推理、自动化与决策视图。**
3. 组合产品的核心卖点是**双入口 + 人类审批闭环**：
   - Web `/console`：商品、刊登、订单、库存、采购、成本、财务、待审、审计。
   - Desktop（OpenMCP Station）：自然语言问数、Agent 巡检、候选/改价/补货建议、Skills、Dashboard、Automations、MCP Apps。
   - 两者不共享数据库；Desktop 通过 OAuth + MCP 读取 ERP，写入只创建 `pending_actions`，最终确认仍在 `/console/pending`。
4. 落地页结构从「沙盒能力/按量计费」改为：**双入口 → AI 运营闭环 → 核心能力 → 安全治理 → 接入方式 → 快速开始**。
5. 本次只产出方案与线框图；代码生成前需确认 §8 的 6 项内容（品牌名、可用性口径、定价、平台范围、i18n、素材）。
6. 不虚构未实现能力：MCP 首版工具范围是 **Daraz 斯里兰卡（LK）**；TikTok/Shopee 价库写回、JSB 官方交运、部分国家独立税栈继续如实标为不支持或规划中。

### 1.3 Desktop / OpenMCP 侧可宣传能力

来自 `/root/workspaces/work-node/openmcp-buddy`：

- **Desktop**：Electron + OpenCode，本地文件/浏览器操作，任意模型。
- **External MCP**：OAuth `per_member` 或 API Key `shared`，组织/团队/成员级授权。
- **能力网关**：`/mcp/agent` 只暴露 `search_capabilities` / `execute_capability`，避免工具膨胀上下文。
- **Skills**：把选品、刊登、成本、补货、复盘等 SOP 固化。
- **MCP Apps**：聊天内联与 Dashboard tile，可承载候选卡、审批卡、成本计算器。

- **Dashboard**：老板驾驶舱。

- **边界**：不直连 ERP 数据库、不保存平台凭证；首版 Agent 不开放 `pending.confirm` / `pending.reject`。

## 2. 产品定位与叙事

### 2.1 一句话定位

> **Open Shop 是跨境电商的事实与审批中枢；OpenMCP Station 是运营团队的 AI 工作台。两者合起来，让 Agent 在真实经营数据上干活，关键动作仍由人拍板。**

### 2.2 对外叙事三层

```text
第一层（老板/负责人）
  每天 5 分钟看懂生意：营收、利润、订单、库存风险、异常与待审。

第二层（运营/选品/财务）
  AI 帮你找异常、算成本、出建议、写草稿；你在 ERP 里确认和执行。

第三层（IT/管理员）
  一套组织、权限、审计与连接管理；数据不出 ERP，写操作可控可回溯。
```

### 2.3 差异化（必须出现在落地页）

1. **双入口，不是二选一**：密集表格和批量操作留在 Web；发现、解释、审批放在 Desktop。
2. **Human-in-the-loop**：Agent 默认只读，写操作只进待审，最终确认只在 ERP。
3. **数字可解释**：成本、税率、汇率、运费、毛利都能展开来源与时间。
4. **本地文件进入工作流**：Desktop 可读供应商报价 PDF/图片、装箱单，这是纯 Web ERP 做不到的。
5. **多客户端**：OpenMCP Station、Claude Code、Codex、Cursor 等都能通过 MCP 使用同一套能力。
6. **可私有化**：ERP 独立部署，适合对数据敏感的大卖家。

### 2.4 不能出现的表述

- ❌ “全自动改价 / 自动发布 / 自动打款”
- ❌ “支持所有平台”或把 TikTok/Shopee 写成完整 ERP 同步
- ❌ “AI 直接操作店铺后台”
- ❌ GPU、沙盒、vCPU、Serverless、模型 API
- ❌ 未确认的价格、客户 Logo、融资/规模数据

| 能力 | 说明 |
| --- | --- |
| 按组织授权 | OAuth token 绑定单一 `organization_id`；切换组织不会改变已发出的 token。 |
| 默认只读 | MCP 首版以读取为主；写工具需要 `openshop:write.pending` scope。 |
| 人工确认 | Agent 不能确认/拒绝待审；最终确认只在 `/console/pending`。 |
| 数据脱敏 | 买家姓名、电话、详细地址、邮箱不进入 Agent 返回内容。 |
| 平台凭证隔离 | Daraz/Lazada 凭证只存 ERP，Desktop 不保存、不直连数据库。 |
| 可审计 | 写操作记录 actor、client、org、requestId 与前后差异。 |
