# 评论数据查看 UED（租户端）

> 状态：设计稿  
> 范围：`apps/shop`（租户端控制台）  
> 目标：在租户端增加「评论」页面用于查看抓取/分析后的评论数据。评论抓取为后台进程，用户无须感知；用户只需查看评论列表、分析摘要和 HTML 报告入口。

## 1. 设计目标

- **后台抓取，前台只读**：抓取（API 优先 + AI 兜底）、去重、情感分析、翻译均在后台/工具链完成。前端仅消费已入库或静态产物（JSON/HTML）数据。
- **与现有壳层一致**：遵循 `(console)/layout.tsx` 嵌套布局、`@workspace/ui` + shadcn、FilterBar + DataTable、抽屉/Sheet 用法（§4/§5 of crossborder-shop-ued-product-design）。
- **最小改动**：新增路由和页面，不破坏现有选品/商品/订单流程。
- **可溯源**：标注数据来源（API/AI 混合）、抓取时间、实抓数 vs 平台数。
- **导出友好**：提供「查看 HTML 报告」入口（链接到 `docs/comments/*.html` 或后续托管路径）。

## 2. IA 与路由

### 2.1 导航位置
建议加入侧栏「运营」或「商品」组，命名「评论」：

```text
侧栏（lean）
├── 仪表盘
├── AI 选品
├── 商品（可选：刊登/商品库）
├── 订单
├── 库存
├── 成本
├── 财务
├── 评论        ← 新增（只读）
├── 待审
└── 设置（底部）
```

### 2.2 路由设计
```text
/[locale]/console/reviews                # 评论列表页（按商品聚合或直接列表）
/[locale]/console/reviews/[itemId]      # 单品评论详情页（评分分布 + 全部评价 + 分析摘要）
/[locale]/console/reviews/reports       # HTML 报告列表（可选）或直接外链
```

首版推荐 **列表页（按商品聚合） + 详情页（单品）**，最符合「用户需要看到评论数据」诉求。

## 3. 页面规格

### 3.1 评论列表页（`/console/reviews`）

**目标**：快速筛选有评论的商品，查看概览（评分、数量、正负向占比）。

**区块**：
| 区块 | 说明 |
|---|---|
| 页头 | 标题「评论」、副标题「查看已抓取的商品评论数据」 |
| FilterBar | 关键词（商品名/Item ID/SKU）、平台（Daraz/Lazada/Tiktok，MVP 先 Daraz）、店铺（如有多店）、有图（是/否） |
| 概览卡片（可选） | 总商品数、总评论数、平均评分、负向占比 |
| DataTable | 商品、主图、Item ID、平台评分/实抓数、平均分、正/中/负、最后抓取时间、操作（「查看详情」「查看报告」） |

**表格列（建议）**：
| 列 | 类型 | 说明 |
|---|---|---|
| 商品 | 链接 | 主图 + 标题，链接到详情页 |
| 平台 | Badge | daraz/lazada 等 |
| Item ID | 文本（复制） | 外部商品 ID |
| 平台评分 | 数值 | 平台展示分数（如 4.75） |
| 实抓/平台总数 | 数值 | `26 / 32` 格式 |
| 平均分（实抓） | 数值 | 样本平均分 |
| 情感概览 | 微型条/文案 | `正12 / 中4 / 负6` |
| 最后抓取 | 时间 | `YYYY-MM-DD HH:mm`，标注 `API`/`AI`/`混合` |
| 操作 | 按钮组 | 「查看详情」主按钮、「HTML 报告」（新窗口） |

### 3.2 单品评论详情页（`/console/reviews/[itemId]`）

**目标**：完整展示评论数据和分析摘要，涵盖 HTML 报告的核心内容但适配控制台布局。

**布局**：页头 + 商品卡片 + KPI + Tabs 或纵向区块（参考选品详情 `candidates/[id]` 样式，避免过多嵌套 Tabs）。

**区块设计**：
| 区块 | 说明 |
|---|---|
| 页头 | 面包屑（评论 > 商品名）、标题、状态（数据最新性）、操作（「查看 HTML 报告」「刷新元数据」） |
| 商品卡片 | 主图、标题、店铺、价格、Item ID、平台链接（新窗口） |
| KPI 卡片 | 实抓、样本平均分、正向/中性/负向、带图数（沿用样例风格但用 `@workspace/ui` Card） |
| 数据说明 | 平台 vs 实抓差额、高分差评提示（小型 Note） |
| 评分分布 | 水平条形图（纯 CSS 或轻量图表，复用现有 Chart 组件思路） |
| 关键发现 | 卖点/痛点/机会点/建议（自动生成，后续可编辑） |
| 评论列表（筛选） | 筛选：全部/正向/中性/负向、高分差评、带图、星级；列表项卡片（星级、买家、SKU、原文、中文、图片、标签） |
| 抓取元数据 | 底部折叠：抓取方式、时间、去重数、来源（API/AI） |

**评论卡片（列表项）**：
- 头部：星级 + `Tag`（pos/neu/neg/void） + `Tag`（高分差评） + 时间 + 买家（脱敏）
- SKU：`Badge outline`
- 内容：原文 + 中文（如有）分行展示
- 备注：分析备注（如样例中的 `💡 ...`）
- 图片：缩略图（点击新窗口）
- 点赞：如有显示

### 3.3 HTML 报告入口（`/console/reviews/reports` 或嵌入）

首版可直接在详情页提供「查看 HTML 报告」按钮，链接到：
- 本地静态：`/docs/comments/<文件名>.html`（如部署环境可访问）或
- 存储桶 URL（后续）

列表页也可在操作列加「报告」链接。

## 6. 数据模型（前端视角）

前端只需消费以下视图模型：

```typescript
// 列表项（聚合）
interface ReviewItemSummary {
  platform: 'daraz'|'lazada'|'tiktok_shop'
  shopExternalId?: string
  itemId: string
  title: string
  imageUrl?: string
  platformRating?: number
  platformCount?: number
  fetchedCount: number
  avgRating: number
  pos: number; neu: number; neg: number
  hasImage: boolean
  lastFetchedAt: string
  source: 'api'|'ai_scrape'|'mixed'
  reportUrl?: string
}

// 详情
interface ReviewDetail {
  product: { itemId:string; title:string; imageUrl?:string; price?:string; shopName?:string; platformUrl?:string }
  kpis: { total:number; avg:number; pos:number; neu:number; neg:number; withImage:number }
  ratingDist: Array<{star:1|2|3|4|5; count:number; pct:number; actualCount:number}>
  insights: { pros:string[]; cons:string[]; opportunities:string[]; notes:string[] }
  reviews: DomainReview[]  // 复用 marketplace domain 类型
  meta: { fetchedAt:string; source:string; totalFetched:number; deduped:number }
}
```

数据来源：可先用静态 JSON（从工具链产出）或后续接 tRPC。

## 7. 实现建议

### 7.1 文件结构
```text
apps/shop/src/app/[locale]/console/(ops)/reviews/
├── page.tsx                    # 列表页
├── [itemId]/
│   └── page.tsx                # 详情页
└── _components/
    ├── review-kpis.tsx
    ├── review-rating-dist.tsx
    ├── review-card.tsx
    ├── review-filters.tsx
    └── review-insights.tsx
```

### 7.2 导航接入
在控制台侧栏配置中新增「评论」项，指向 `/{locale}/console/reviews`，图标用 `MessageSquare` 或 `Star`（lucide-react）。

### 7.3 权限
租户端只读本组织相关数据（如关联店铺的商品）。平台运营后台可跨租户查看。

### 7.4 性能
列表用服务端过滤（searchParams），详情页一次加载全部评论（样本通常 < 100 条），无需复杂分页。

## 9. 与后台设计的衔接

后台抓取产出需满足：
- `docs/comments/*.html`（人类可读报告）
- JSON 数据（供前端消费，可放 `apps/shop/public/data/reviews/` 或通过 API 返回）
- 元数据包含 `source`、`fetchedAt`、`platform`、`itemId`

前端仅展示，不触发抓取。
