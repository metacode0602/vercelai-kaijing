## 一、开始之前：你必须完成的准备工作

设备自动上架不是"上传一张 Excel 就结束"。在平台能自动纳管你的设备之前，需要完成以下准备工作。**跳过任何一步都会导致后续设备接入失败。**

### 1.1 前置条件检查清单

| 序号 | 检查项 | 谁来做 | 完成后状态 | 预计耗时 |
|:----:|--------|--------|-----------|---------|
| ① | 供应商资质审核通过 | 平台运营 | 可登录供应商门户 | 1-3 工作日 |
| ② | 创建机房 | 供应商 | 机房记录已创建 | 10 分钟 |
| ③ | 获取 Agent Token | 平台运营 | 向供应商交付 `agent_token` | 运营响应时间 |
| ④ | 部署管控节点 + Edge Agent | 供应商 | Agent 在线，平台可下发任务 | 30 分钟 |
| ⑤ | 确认管控节点可 SSH 到所有 GPU 节点 | 供应商 | 管控节点内网 ping 通所有目标设备 | 视内网规模而定 |

**只有 ①-⑤ 全部完成后，才能开始上传设备批次。** 如果跳过步骤 ④，设备只会在审核后卡在"等待 Agent 执行"状态，永远无法自动上线。

### 1.2 前置条件详解

#### ① 供应商资质审核

在 `apps/supplier` 完成企业注册，提交资质文件（营业执照、法人身份证）后，等待平台运营审核。审核通过后你可以登录供应商门户控制台。

**你在这个阶段可以提供的信息**（加速后续流程）：

| 信息 | 说明 | 示例 |
|------|------|------|
| 预计上架 GPU 卡型与数量 | 方便运营提前准备 GPU 卡型主数据 | H100-80G × 200 台，A100-80G × 100 台 |
| 机房网络拓扑 | 内网 CIDR、公网出口带宽、防火墙策略 | 10.0.0.0/16，1Gbps 出口 |
| 管控节点规划 | 用于部署 Edge Agent 的服务器规格 | 1C/2G/20G Ubuntu 22.04 |

#### ② 创建机房

登录供应商门户 → 机房管理 → 新建机房。填写真实的机房信息：

| 字段 | 重要性 | 说明 |
|------|--------|------|
| 机房名称 | 展示用 | 如 "上海张江 H100 集群" |
| 机房编码 | **关键** | 供应商内唯一编码，后续设备 Excel 中的 `idc_code` 必须与此一致 |
| 所在城市 | 调度用 | 影响跨区域调度决策 |
| 内网网段 | **关键** | 管控节点和 GPU 节点必须在同一/可达网段 |
| 运维联系人 | **关键** | 平台需要联系你时使用 |

#### ③ 获取 Agent Token

机房创建完成后，联系平台运营获取 `agent_token`。运营会在 `apps/web` 为该机房生成唯一的 agent_token。

**Agent Token 是管控节点注册的唯一凭证，请妥善保管，不要泄露。**

#### ④ 部署管控节点 + Edge Agent

这是最关键的步骤。你需要：

**硬件要求**：
- 1 台低配服务器或 VM（1C/2G/20G 即可）
- Ubuntu 22.04（推荐）或 Rocky Linux 9
- 必须能通过内网 SSH 到所有 GPU 节点
- 必须能通过 HTTPS（443 端口出站）访问平台 API

**部署步骤**：

```bash
# 在管控节点上执行（平台运营会提供实际的 TOKEN 和 API_URL）
curl -fsSL https://agent.GPURun.cn/install.sh | sudo bash -s -- \
  --token "YOUR_AGENT_TOKEN" \
  --api-url "https://api.GPURun.cn" \
  --datacenter "SH-ZJ-01"
```

**部署后验证**：

```bash
# 检查 Agent 是否运行
sudo systemctl status GPURun-agent

# 查看日志
sudo journalctl -u GPURun-agent -f

# 看到类似以下日志即为注册成功：
# [INFO] agent registered | agent_id=agent-xxx | datacenter=SH-ZJ-01
# [INFO] heartbeat sent | status=ok
```

Agent 注册成功后，通知平台运营确认 Agent 在线。运营在后台看到 Agent 状态为 `online` 后，设备上架流程才能真正启动。

#### ⑤ 确认管控节点网络可达

在管控节点上执行以下验证：

```bash
# 对每台 GPU 节点测试 SSH 连通性
ssh -o ConnectTimeout=5 root@10.0.1.101 "echo OK"
ssh -o ConnectTimeout=5 root@10.0.1.102 "echo OK"
# ... 逐台测试
```

**如果管控节点无法 SSH 到某台 GPU 节点，请检查**：
- 防火墙规则（22 端口）
- 内网路由
- GPU 节点的 SSH 服务是否开启

## 二、设备类型说明：四种设备，四种上传方式

### 2.1 为什么要分开？

平台的设备分为四种角色，它们的**生命周期、纳管流程、池归属、计费模型完全不同**：

| 维度 | 管控节点 (1-3台) | 计算节点 (Worker) (数十~数百台) | 可切换节点 (Convertible) (数台~数十台) | 裸金属节点 (数台~数十台) |
| :--- | :--- | :--- | :--- | :--- |
| 角色 | Edge Agent<br>K8s 控制面<br>平台基础设施 | GPU 容器工作负载<br>K8s worker | 容器 ↔ 裸金属动态切换<br>K8s worker + 网关代理 | 整机出租，不虚拟化<br>SSH 直连或网关代理 |
| GPU | 如有可复用 (低优spot) | 有 (出售)<br>按GPU-小时计费 | 有 (出售)<br>容器/裸金属双计费 | 有 (出售)<br>按整机-天/周/月计费 |
| 池 | 无<br>低优elastic | elastic (弹性池) | elastic+dedicated (双池，可切换) | dedicated (专属池) |
| 上传 | 一次性设置<br>不通过批次 | 批量 Excel<br>批次管理 | 单独批次<br>需选 `bare_metal_mode` | 单独批次<br>需选 `bare_metal_mode=direct/gateway_direct` |
| 下架 | 永不下架 | 可申请下架<br>提前24h通知 | 裸金属订单优先<br>容器负载需先迁移 | 租期结束自动释放 |


**混在一起会导致的问题**：

1. 管控节点和计算节点混在一起 → 平台不知道哪些设备需要装 K8s 控制面，哪些只需要装 kubelet
2. 可切换节点和纯计算节点混在一起 → 调度引擎不知道哪些设备可以安全转裸金属（纯计算节点上的 on_demand 负载不可驱逐）
3. 可切换节点和纯裸金属节点混在一起 → 纯裸金属无法接入 K8s，平台将浪费时间尝试 SSH 加入集群
4. 单批次混合不同 GPU 卡型 → 上架策略无法统一应用

### 2.2 四种设备的上传模板

#### 类型一：管控节点（每机房一次性设置）

管控节点不需要通过批次上传。在机房创建后，由平台运营在后台配置。供应商只需在机房信息中提报管控节点的 IP 和凭据。

**供应商无需额外操作。** 只需确保步骤 ④ 中的管控节点已部署 Agent 并在线。

**关于管控节点 GPU**：如果管控节点有 GPU，平台可以将其作为低优 spot 容量出售（不影响管控组件运行）。你无需在上传时特殊标记——系统在 GPU 检测阶段会自动发现。是否启用 GPU 复用由平台运营决定。

#### 类型二：计算节点（批量上传）

**适用场景**: 纯容器化 GPU 工作负载，接入 K8s 弹性池，按 GPU-小时计费。固定留在弹性池，不参与裸金属出租。

| 列名 | 必填 | 说明 | 示例 |
|------|:--:|------|------|
| `sn` | ✅ | 设备序列号，全局唯一 | `SN2026A10001` |
| `gpu_card_type` | ✅ | GPU 卡型编码 | `H100-80G` |
| `gpu_count` | ✅ | GPU 数量（1/2/4/8） | `8` |
| `internal_ip` | ✅ | 内网 IP（管控节点可达） | `10.0.1.101` |
| `idc_code` | ✅ | 机房编码（与机房管理中一致） | `SH-ZJ-01` |
| `device_role` | ✅ | 固定填 `compute` | `compute` |
| `network_mode` | ✅ | `standalone` / `nvlink` / `infiniband` / `roce` | `nvlink` |
| `root_username` | ✅ | SSH 登录用户名 | `root` |
| `root_password` | ✅ | SSH 密码（上传后加密存储） | `***` |
| `cooperation_type` | ✅ | `idle_time`（闲时）或 `whole_rent`（整租） | `idle_time` |
| `remark` | — | 备注 | `H100 NVLink 8卡，512GB RAM` |

**重要约束**：
- **同批次必须同一合作模式**（`cooperation_type` 不能混）
- **同批次必须同一网络模式**（`network_mode` 不能混）
- **同批次建议同一 GPU 卡型**

#### 类型三：可切换节点（单独批次）⚠️ 高级

**适用场景**: 设备既能作为 K8s 容器节点，也能在用户租用裸金属时切换为整机出租。**所有网络模式均支持。**

| 列名 | 必填 | 说明 | 示例 |
|------|:--:|------|------|
| `sn` | ✅ | 设备序列号 | `SN2026CV001` |
| `gpu_card_type` | ✅ | GPU 卡型编码 | `A100-80G` |
| `gpu_count` | ✅ | GPU 数量 | `8` |
| `internal_ip` | ✅ | 内网 IP | `10.0.3.1` |
| `idc_code` | ✅ | 机房编码 | `SH-ZJ-01` |
| `device_role` | ✅ | 固定填 `convertible` | `convertible` |
| `network_mode` | ✅ | `standalone` / `nvlink` / `infiniband` / `roce` | `nvlink` |
| `bare_metal_mode` | ✅ | 裸金属阶段的租户接入方式 | `gateway_direct`（推荐） |
| `root_username` | ✅ | SSH 登录用户名 | `root` |
| `root_password` | ✅ | SSH 密码 | `***` |
| `cooperation_type` | ✅ | `idle_time`（闲时） | `idle_time` |
| `remark` | — | 备注 | `A100 8卡，容器/裸金属可切换` |

**bare_metal_mode 怎么选**：

| bare_metal_mode | 适合场景 | 要求 |
|----------------|---------|------|
| `gateway_direct`（推荐） | 设备已在平台网关可达范围内（Edge Agent 就是通过网关纳管的）。租户通过网关访问设备。 | 无额外要求——网关已有内网通路 |
| `gateway_proxy` | 设备需要通过网关代理转发 SSH/RDP。支持裸金属和 K8s 同时在线。 | 同 gateway_direct |
| `direct` | 租户直接 SSH 到设备（不走网关）。适合有公网 IP 或租户 VPN 接入的场景。 | ⚠️ 必须提供租户可达的 IP |

**与前两种类型的区别**：
- 上线后默认走容器调度（同 compute）
- 当有用户租用裸金属且选中此设备时，会自动迁移容器工作负载并切换为裸金属模式
- 裸金属租期结束后自动恢复为容器节点
- **设备上的 on_demand 容器工作负载无法被迁移**——如果设备正被 VIP 租户使用，裸金属订单会拒绝分配此设备
#### 类型四：裸金属节点（单独批次）

**适用场景**: 纯整机出租（不经过 K8s 虚拟化），按天/周/月计费。不参与容器调度。

| 列名 | 必填 | 说明 | 示例 |
|------|:--:|------|------|
| `sn` | ✅ | 设备序列号 | `SN2026BM001` |
| `gpu_card_type` | ✅ | GPU 卡型编码 | `A100-80G` |
| `gpu_count` | ✅ | GPU 数量 | `8` |
| `internal_ip` | ✅ | 内网 IP | `10.0.2.1` |
| `idc_code` | ✅ | 机房编码 | `SH-ZJ-01` |
| `device_role` | ✅ | 固定填 `bare_metal` | `bare_metal` |
| `bare_metal_mode` | ✅ | `direct`（直连）或 `gateway_direct`（网关直连） | `direct` |
| `root_username` | ✅ | SSH 登录用户名 | `root` |
| `root_password` | ✅ | SSH 密码 | `***` |
| `cooperation_type` | ✅ | `idle_time`（短租）或 `whole_rent`（长租） | `idle_time` |
**网络模式与 device_role 映射速查**：

| bare_metal_mode | 适用 device_role | K8s 纳管 | 池归属 | 说明 |
|----------------|-----------------|---------|--------|------|
| `gateway_direct`（推荐） | `convertible`、`bare_metal` | ✅ 弹性池阶段在 K8s 中 | elastic ↔ dedicated | 通过网关暴露，Edge Agent 已有内网通路 |
| `gateway_proxy` | `convertible` | ✅ 弹性池和裸金属可同时在线 | elastic + dedicated | 网关代理转发，支持双模并存 |
| `direct` | `convertible`（需公网 IP）、`bare_metal` | ✅（弹性池阶段） | elastic ↔ dedicated | 租户直连 SSH，适合有公网 IP 的场景 |
| （不适用） | `compute` | ✅ 在 K8s 池 | elastic（固定） | 纯容器，不可切换 |

### 第一步：确认前置条件

对照 §1.1 的检查清单，确认所有 5 项全部完成。**特别是管控节点 Agent 必须已在线。**

### 第二步：下载 Excel 模板

在供应商门户 → 设备管理 → 创建上架批次 页面下载模板：

- **计算节点模板**: `worker_device_template.xlsx` — 包含 §2.2 类型二的所有列
- **裸金属节点模板**: `baremetal_device_template.xlsx` — 包含 §2.2 类型三的所有列

### 第三步：填写设备清单

**DO**：
- 逐台核对 SN（序列号必须与设备物理标签一致）
- 逐台 ping 测试内网 IP
- 逐台确认 SSH 用户名密码可用
- 同批次使用相同的 `cooperation_type` 和 `network_mode`

**DON'T**：
- 不要在一个批次中混入管控节点
- 不要在计算节点批次中混入裸金属节点
- 不要使用猜测的 GPU 卡型（使用 [支持的 GPU 卡型清单] 中的编码）
- 不要重复使用已上传过的 SN

### 第四步：上传批次

1. 登录供应商门户 → 设备管理 → 创建上架批次
2. 选择目标机房
3. 选择设备类型：「计算节点」或「裸金属节点」
4. 上传填好的 Excel
5. 系统自动校验格式（字段非空、SN 格式、GPU 卡型有效性）
6. 提交

### 第五步：等待自动处理

提交后系统自动进行：

```
Excel 解析 → 写入设备主数据 → 运营审核 → 设定上架策略
  → Edge Agent 拉取任务 → SSH 验证 → GPU 对账 → 环境初始化
  → K8s Join → GPU 插件安装 → 标签污点 → 健康检查 → 上线
```

**你在供应商门户可以看到每台设备的实时阶段**：

| 状态 | 含义 | 你需要做什么 |
|------|------|------------|
| 🟡 待审核 | 等待平台运营审核设备信息 | 无需操作，等待 |
| 🟡 审核中 | 运营正在审核 | 无需操作 |
| 🔴 审核驳回 | 设备信息有问题 | 查看驳回原因 → 修正 → 重新提交 |
| 🟡 接入中 | Edge Agent 正在执行上架流水线 | 无需操作，可展开查看当前阶段 |
| 🟢 已接入 | 设备已成功上线，可被调度 | 可在设备详情查看实时占用状态 |
| 🔴 接入失败 | 某个阶段失败 | 查看失败原因 → 修正 → 点击「重试」 |

### 第六步：验证上线

设备显示「已接入」后：

1. 在设备列表确认设备状态为 🟢 在线
2. 点击设备详情，确认 GPU 数量与上报一致
3. 等待 1-2 小时，确认设备开始产生计费卡时
4. 在账单管理中查看收入

## 四、常见问题排查

### Q1: 设备一直显示「待审核」怎么办？

联系平台运营确认审核进度。如果超过 1 个工作日未审核，可通过飞书群或站内信催促。

### Q2: 设备显示「SSH 不可达」怎么办？

1. 确认管控节点 Agent 是否在线（`systemctl status GPURun-agent`）
2. 从管控节点手动 SSH 到目标设备测试
3. 检查防火墙是否开放 22 端口
4. 检查 IP 是否填写正确
5. 修正后在供应商门户点击「重试」

### Q3: 设备显示「GPU 不匹配」怎么办？

nvidia-smi 检测到的 GPU 与你上报的不一致：

1. 确认填写的 `gpu_card_type` 编码是否正确
2. 确认 GPU 数量是否正确（是否是 8 卡但只插了 4 卡？）
3. 检查 GPU 驱动是否正常安装（`nvidia-smi` 是否可用）
4. 联系平台运营确认 GPU 卡型编码是否在系统中存在

### Q4: 上传 Excel 后提示「SN 已存在」？

该 SN 已在系统中注册（可能是其他供应商或之前的批次）。如果确认属于你，联系平台运营处理设备归属。

### Q5: 管控节点宕机了怎么办？

管控节点宕机会导致该机房所有设备的 SSH 操作（重试、健康检查）暂停。已经上线的设备不受影响（继续运行、计费）。

**应急方案**：
1. 尽快恢复管控节点（重启、重建）
2. Agent 重启后自动重新注册
3. 如果有备用管控节点，联系平台运营切换 Agent Token 绑定

## 五、日常运营

### 5.1 查看设备实时状态

供应商门户 → 设备管理 → 设备列表：

- 在线设备数、总 GPU 数、可用 GPU 数
- 每台设备的业务类型（容器/裸金属/闲置）
- 占用详情（哪个租户占用了多少 GPU）
- 合作模式、在线时长

### 5.2 修改合作模式

设备上线后可以更改合作模式（`idle_time` ↔ `whole_rent`）：
- 单台修改：设备详情 → 编辑合作模式
- 批量修改：设备列表 → 勾选多台 → 批量修改

**注意**：修改合作模式可能需要平台运营审核（尤其涉及计费模型变更时）。

### 5.3 申请设备下架

提前 24 小时申请：

1. 设备管理 → 设备下架 → 新建下架批次
2. 选择需要下架的设备
3. 填写下架原因
4. 提交 → 等待平台运营审批
5. 审批通过后，系统自动执行：Cordon → Drain → Delete Node → 资源回收
