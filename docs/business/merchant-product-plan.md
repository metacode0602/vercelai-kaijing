## 1. 背景与目标

### 1.1 背景

GPURun Cloud（GPURun）已具备：

- **运营中台**（`apps/web`）：商户主数据、进货价、区域/卡型配额、充值、账单 rollup、租户归属等 CRM 能力较完整。
- **商户门户脚手架**（`apps/merchant`）：登录/入驻、控制台壳（租户/定价/账单/充值）、品牌装修 UI（多为本地 Demo 状态）；本期将作为 OEM 客户侧**白牌管理后台**基座，部署在客户域名下。
- **终端用户控制台**（`apps/gpus`）：云主机 / 裸金属 / Serverless / 任务页等，算力任务多经本机 tRPC → SkyPilot 等服务，而非统一经 `apps/api`。
- **OpenAPI**（`apps/api`）：目前主要有健康检查、充值、裸金属订单等，**尚不具备**完整「任务发布/查询/修改/监控」对外接口面。

商业文档将商户定义为渠道杠杆：按 **L3 进货价**拿货、自主定价销售，平台赚批发差价（收入项 **R3：分销 / OEM 渠道分润**）。商户接入的**商业口径**为 **OEM（Self-Host）品牌独立站 / IFrame / Promo 推广链接** 三种（见本文 §5 模式 A / B 与 IFrame 能力开关）；数据模型 `access_mode` 快照枚举另含 `api`，读取一律走能力派生值（D3-2=A）。

### 1.2 本次目标（用户确认范围）

补齐并落地 **商户以算力分销为主业** 的产品闭环，明确两种经营模式，并在方案确认前不改动业务功能代码：

| 模式 | 名称 | 一句话 |
| --- | --- | --- |
| **A** | **推广链接** | 商户生成带归因的推广/邀请链接，终端用户仍使用平台（或约定站点）完成注册/充值/用算力，消耗与佣金归因到商户。 |
| **B** | **品牌 OEM** | 商户拥有**独立部署、独立域名、独立数据库**的品牌站；在**客户域名上的白牌** `apps/merchant` 管理 OEM 可售服务与**卡型定价**；品牌站登录/注册/充值使用品牌方主题；算力**任务**的发布/获取/修改/监控经品牌站 tRPC 调用 **`apps/api`**。 |

### 1.3 非目标（本期方案层）

- 不在确认前实现任何功能代码或提交/推送。
- 不替代供应商域成本价（`supplier_unit_cost`）与平台 L1（含机房级覆盖）/ L2 成本定价主责。
- **不做抽取共享包**作为 OEM 复用路径（见 C1）；品牌站与平台拆分部署、独立库（见 C3–C5），与「同库多租户白牌外壳」不同。**客户自托管**（Q18=B）：平台只提供制品与 `apps/api`，**不等同于**整栈源码私有化交付。
- 不在本期重做销售提成矩阵（`docs/business/cost.md` 面向内部销售/市场/中台），与商户渠道分润可并存但口径分离。

| **OEM 品牌站** | **尚未创建**的独立前端应用（可 fork/复制 gpus 起步）；**独立域名、独立 DB、与平台拆分部署**；对终端用户呈现商户品牌；能力对齐 gpus，差异见 §5。 |

## 3. 商业模式对齐

### 3.1 商业文档要点（引用）

摘自 `docs/business/商业方案.md` / `docs/business/商业方案-投资人版.md`：

- **三位一体**：产品化 + 计量化 + **分销化**。
- **四层定价**：L1 平台刊例价（含机房级子维度）→ L2 机房成本价（仅核算，不参与计费）→ **L3 商户进货价** → **L4 商户销售价**（支撑分销/OEM）。
- **§3.5 商户与渠道**：接入模式 **OEM（Self-Host）品牌独立站 / IFrame / Promo 推广链接**（`access_mode` 快照枚举另含 `api`，读取走能力派生值）；覆盖进货价、充值、账单、区域与卡型价目、商户租户管理。
- **收入 R3**：商户按进货价拿货、自主定价销售，平台赚批发差价；渠道自带获客。
- **原则**：渠道是杠杆——OEM 商户自带客户，平台让渡部分差价换取零边际获客成本。

`docs/business/cost.md` 描述的是**内部销售提成**（毛利基数 × 提点），与商户分销结算不同：商户侧核心是 **进销差价 / 渠道结算**，不宜直接复用提成矩阵表。

`../design/audit/design-vs-schema-conflicts.md`：商户域 Schema 已显著超前早期设计表清单；进货价、区域、账单等多数已在 `packages/db/src/merchant-schema.ts`；**销售价表 Schema 已建**（`merchant_sales_price`）；推广归因、OEM 品牌站按现网复核为准。在 v0.2 约束下，OEM 还涉及**品牌站独立库 Schema** 与平台库之间的边界（见 §7、§10）。

### 3.2 两种模式与商业文档的映射

| 用户模式 | 与文档关系 | 价值主张 |
| --- | --- | --- |
| **A 推广链接** | 偏「渠道获客 / 归因分润」；落地站**仅官方 `apps/gpus`**（Q2=A）；收益按进销价差与 OEM 同结算（Q4=B）。 | 低成本获客；商户无需维护站点。 |
| **B 品牌 OEM** | 对齐文档 **OEM 白标**；`access_mode=oem`；商户控制台管服务与卡型销售价；**独立站 + 独立库 + 拆分部署**。 | 商户自有品牌与域名体验；平台做底层算力与计量（经 `apps/api`）。 |

**IFrame / 纯 API** 可作为后续扩展（商务已有枚举），本期产品主路径按用户要求收敛为 **A + B**。

### 3.3 资金与价差逻辑（对齐现有设计）

```text
平台 L1 刊例（含机房级覆盖）/ L2 机房成本
        ↓（CRM 配置，平台库权威）
商户进货价 merchant_purchase_price  → 定时/事件同步副本到品牌站库（Q15=B）
        ↓（商户控制台配置，硬约束 ≥ L1 刊例价 × {比例待定}，现实现为 ≥ 进货价；销售价写品牌站库）
商户销售价 merchant_sales_price  → 终端价；未配置时默认 = 平台刊例价（Q5=C）
        ↓ 消耗
租户账单 / 商户账单 rollup → 平台与商户结算（进销价差，A/B 同口径 Q4=B）
```

## 4. 两种模式详细说明

### 4.1 模式 A：推广链接（Referral / Promo Links）

> **落地页表述按原文不动**（约束 C2）。本节相对 v0.1 不改写落地页产品语言。

#### 用户流程

1. 商户在控制台创建推广活动/链接（名称、落地产品、有效期；收益按**进销价差**与 OEM 同结算，Q4=B）。需显式开通推广 feature flag（Q11=B）。
2. 系统生成唯一 `promo_code` / 短链，落地**仅官方 `apps/gpus`**（Q2=A），例如：`https://gpus.example/{locale}/signup?m={merchantCode}&r={promoCode}`。
3. 终端用户点击链接 → 注册/登录时写入 **邀请归因**（首次归因优先，防刷策略实施期细化）。
4. 用户在 **官方 `apps/gpus`** 完成充值与用算力；推广注册用户的 `tenant.merchant_id` **直接等于**推广商户（Q3=A）。
5. 商户在控制台查看：链接点击/注册/充值/消耗/预估收益（价差口径）。

#### 核心能力

| 能力 | 说明 | 优先级建议 |
| --- | --- | --- |
| 推广链接 CRUD | 创建、停用、复制短链、二维码 | P0 |
| 归因绑定 | 注册/首充与 `merchant_id`（或 referral 记录）关联 | P0 |
| 数据看板 | 注册数、充值额、消耗、预估佣金 | P0 |
| 结算视图 | 与商户账单/回款节点对齐（进销价差，与 OEM 同结算） | P1 |
| 防刷与归因窗口 | IP/设备、归因有效天数、二次覆盖规则 | P1 |

#### 边界

- **不要求**独立 OEM 域名与主题；落地站仅官方 gpus（Q2=A）。（OEM 站内是否挂同一 promo 码本期不做。）
- 终端任务链路继续走 `apps/gpus` 现状（SkyPilot 直连）；官方站**暂不迁** `apps/api`（Q8=A）。
- 商户不可见其他商户链接与租户数据。
- 推广与 OEM 均需独立 feature flag 显式开通（Q11=B）。

### 4.2 模式 B：品牌 OEM

#### 用户流程

1. 商务/CRM 开通 OEM feature flag（及必要时 `access_mode=oem`），授权可售区域/卡型（沿用 `merchant_datacenter_region` / `merchant_datacenter_card_type`，平台库）（Q11=B）。
2. 商户在**客户域名上的白牌** `apps/merchant`（**一套部署按域名多租户**，Q17=A）配置：**品牌主题**、**可售服务清单**、**卡型销售价**；支付/短信/邮箱可配商户自有通道（Q10=B）。
3. 客户**自托管**部署品牌站（独立仓库 fork gpus，Q6'=B / Q18=B），绑定**商户自定义域名（CNAME）**（Q9=A），配备**品牌站独立数据库**。
4. 终端用户访问品牌站：注册/登录/充值页均为品牌主题 → 在品牌站库创建终端用户/租户并归属该商户（品牌站库自洽，Q13=B）。
5. 用户创建/管理算力任务：品牌站 **tRPC** **一律**跨网络调用平台 **`apps/api`**（Q16=A）；账单/镜像等可直连品牌站库（Q7=A）。
6. 销售价写品牌站库；进货价由平台库权威经定时/事件同步副本到品牌站库（Q15=B）；未配销售价时默认刊例价（Q5=C）。商户在白牌控制台（认证平台身份、主读写平台库，Q14=A）看进货成本与毛利。

#### 核心能力

| 能力 | 说明 | 优先级建议 |
| --- | --- | --- |
| OEM 服务管理 | 开关产品线（云主机/裸金属/Serverless/Job/Spot 等）、区域可见性 | P0 |
| 卡型定价 | 查看进货价、设置销售价（≥ 进货价）、按卡型聚合展示 | P0 |

| 品牌站应用 | **独立仓库 fork** gpus；客户自托管；任务经 api | P0 |
| 独立库与部署 | 品牌站 DB Schema、迁移、与平台拆分的发布流水线 | P0 |
| 白牌商户控制台 | 一套 `apps/merchant` 按客户域名多租户 + 客户品牌；认证平台身份、主读写平台库 | P0 |
| 租户/订单/账单 | 商户控制台主读写平台库；品牌站库仅只读或经 api（Q14=A） | P0 |
| 域名与证书、客户自托管运维 | 商户 CNAME、证书与发布由客户侧负责；平台提供制品与 api | P1 |

- OEM 品牌站 **不是** 既有仓库应用；实施阶段以**独立仓库 fork** gpus 起步（Q6'=B），**不做共享包抽取**。

## 5. OEM 品牌站与 apps/gpus 的差异与复用策略

### 5.1 唯一产品差异（用户硬性约定）

> **OEM 品牌站与 `apps/gpus` 的唯一差异**：品牌站对算力**任务**的发布 / 获取 / 修改 / 监控，通过品牌站自身的 **tRPC 层** 调用 **`apps/api`** 接口完成。  
> **登录 / 注册 / 充值** 使用品牌方主题（视觉与文案），能力可与 gpus 对齐但皮肤不同。

含义澄清（方案层）：

| 维度 | apps/gpus（官方） | OEM 品牌站 |
| --- | --- | --- |
| UI/产品功能面 | 完整控制台 | 以 gpus 为**复制/fork 起点**，独立演进；**不**依赖抽取共享包 |
| 部署 / 域名 / DB | 平台部署、官方域、平台库 | **拆分部署、客户独立域名、品牌站独立 DB** |
| 主题 | GPURun 官方 | 商户 Branding（名/Logo/色等） |
| 登录/注册/充值 | 官方主题 | **品牌主题** |
| 任务链路 | 现状：gpus tRPC → 本机 dataaccess / SkyPilot 等 | **品牌站 tRPC → `apps/api`（OpenAPI）→ 平台算力与状态**（跨网络） |
| 其它业务（账单列表、镜像等） | 本机/平台库策略 | **仅任务**走 `apps/api`；账单/镜像等可直连品牌站库或约定服务（Q7=A） |

### 5.2 复用策略（v0.2：不做抽取共享包）

1. **独立仓库 fork 起步（确认，Q6'=B）**：以 `apps/gpus` 为起点在**独立仓库** fork（或品牌站专用仓），与 monorepo 平台仓**分离发布**；**禁止**以抽取共享包为主路径（C1）。后续官方 gpus 与品牌站各自演进，必要同步用 cherry-pick / 移植。  
2. **品牌站独立壳与配置**：路由、站点配置、ThemeProvider 注入 merchant branding；绑定**商户自定义域名（CNAME）**（Q9=A）；连接**品牌站独立 DB**（自洽：用户/租户/销售价/站内账单，Q13=B）。  
3. **任务经平台 api（Q16=A）**：品牌站 tRPC 中 `compute`/`tasks` 等 procedure 一律 HTTP 客户端**跨网络**调用平台 `apps/api`；账单/镜像等可直连品牌站库（Q7=A）。  
4. **apps/api 补齐任务面**：将算力编排能力 **收敛为稳定 OpenAPI**，供品牌站调用；官方 gpus **暂不迁** api，保留 SkyPilot 直连（Q8=A）。  
5. **白牌 `apps/merchant`**：一套部署，按客户域名多租户路由与主题（Q17=A）；商户账号认证**平台身份体系**，控制台主读写**平台库**，品牌站库仅只读或经 api（Q14=A）。  
6. **身份与租户**：品牌站注册用户归属当前 OEM 商户（站内库）；调用平台 api 时携带商户/租户校验所需凭证（实施期细化 token / API Key / trusted origins）。

### 5.3 现状对照（支撑差异落地）

- `apps/gpus`：`compute` / `metal` 等 router 直连服务；`tasks-data.ts` 仍为演示空数据。  
- `apps/api`：已有 `recharge`、`bare-metal` 等，**无**完整任务 OpenAPI。  
- 故「唯一差异」落地的工程前提是：**先让 api 具备任务接口，再让品牌站只走 api**；官方 gpus **暂不迁**，保留 SkyPilot 直连（Q8=A）。  
- **独立库 + 任务走平台 api** 并存（Q13=B / Q16=A）：终端会话/租户在品牌站库自洽；任务权威状态以 api 响应为准、站内可缓存；调用时做商户/租户远程校验。
