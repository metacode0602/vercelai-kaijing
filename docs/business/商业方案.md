## 1. 执行摘要

### 1.1 一句话定位

**我们是一个基于 Kubernetes 的闲时算力调度平台**：通过统一控制面聚合多家 IDC 机房在业务低谷期闲置的 GPU 资源，形成弹性算力池，以云服务器、裸金属、Serverless 推理、批处理 Job、Spot 抢占式实例五种产品形态，按量供给 AI 训练、推理与智能体负载的客户——**让 IDC 的闲置资产产生收益，让客户以远低于大盘的价格拿到可用算力**。

### 1.2 我们解决的两个结构性痛点


| 供给侧（IDC / 算力供应商）                                     | 需求侧（AI 企业 / 开发者）                                            |
| ---------------------------------------------------- | ----------------------------------------------------------- |
| 机房 GPU 上架后利用率长期不足，闲时时段（夜间、周末、批次间隙）电费与折旧照付，资产回报率被闲置吞噬 | 公有云 GPU「一卡难求 + 按月计费 + 溢价高」；训练任务有潮汐，按包月买卡极不划算；小团队无法承担万卡集群的运维 |
| 缺少把闲时资源「标准化、可计量、可SLA」卖出去的产品与通道                       | 需要的是**卡时**，而不是「一台带卡的服务器」                                    |


**我们的答案**：做供给侧的「聚合器 + 调度器 + 计量计费引擎」，做需求侧的「算力商城 + 控制台 + 开放 API」，从中赚取 **供需价差 + 平台服务费 + 增值收入**。

### 1.3 核心亮点（Why Us）

1. **已在线上真实运营的运营中台**——不是 PPT 项目。仓库 `develop-gpus` 为主开发分支，约 1,100 个源码文件、40 次数据库迁移、约 260 张业务表，覆盖 CRM、供应商生命周期、财务成本核算、商户分销、SLA 考核全链路。
2. **完整的产品矩阵设计**——五条核心产品线（云主机 / 裸金属 / Serverless / Job / Spot）+ **独家 Agent Sandbox** × 三层定价体系（平台刊例价 / 机房成本价 / 商户进货价）× 量券与折扣体系，商业闭环已设计并部分落地。
3. **闲时经济学的直接受益者**——Spot 产品对标市场低至 **6 折**（如 H100 按量 2.59 元/时 → Spot 1.55 元/时），价差本身就是最强的增长引擎。
4. **供给侧壁垒**——供应商生命周期管理（看得见 / 接得进 / 管得住 / 算得清 / 追得到）、机房 SLA 考核与赔付、设备探活与对账，构成「资源 × 合约 × 数据」三重护城河。
5. **自建调度引擎是明确的下一阶段**——SkyPilot + Kueue/MultiKueue + Volcano + OpenMeter 的 K8s 调度与计量栈已完成 16 篇、约 1.3 万行架构设计文档，本轮资金将把「依赖外部算力平台」升级为「自有调度闭环」。
6. **独家技术：Agent Sandbox**——不是「又一个容器平台」，而是专门为**执行不可信的 AI 生成代码**和\*\*基于 Agent 的训练（RL）\*\*而设计的执行运行时，与闲时调度、秒级计量闭环打通，目前未见同类组合方案（详见 §3.6）。

### 1.4 融资亮点速览

- **赛道**：AI 算力基础设施 / 算力即服务（CaaS），确定性高、政策强支持（东数西算、算力互联网）。
- **模式**：轻资产聚合调度（不自建机房），毛利来自价差与平台费，规模化边际成本低。
- **现状**：中台已运营、消费者端已完成高保真产品化（含 Agent Sandbox 全套 UED）、调度与计量引擎已完成架构设计。
- **本轮融资用途**：自建 K8s 调度与计量引擎、Serverless 推理闭环、**Agent Sandbox 执行运行时落地**、消费者端交易后端上线、供给侧资源扩张。

## 2. 市场机会

### 2.1 需求侧：AI 算力是新时代的「电力」，且需求高度潮汐化

- 大模型训练、微调、批量推理、AI 智能体（Agent）执行任务，均以 **GPU 卡时**为基本生产资料。
- AI 负载天然具有 **潮汐特征**：训练任务成批到达、推理请求有日夜峰谷、智能体任务在工作时间集中执行。这意味着按「包月独占」采购算力会造成大量浪费。
- 一批新兴客户——**AI 创业公司、独立开发者、算法团队、AIGC 应用方、企业 AI 部门**——对弹性、低价、按量计费的算力有刚性需求，但对百万级包月缺乏支付意愿与能力。
- **Agent 经济的算力增量**：AI 智能体从「思考」走向「动手执行」——运行代码、调工具、连数据、做 RL 训练，每一次 Agent 行动都需要一个短生命周期、可中断、可并发的执行环境，这是传统「租一台机器」模式覆盖不了的全新需求层（详见 §3.6 Agent Sandbox）。

> 我们的消费者端首页定位即为此而生：**「供 AI 智能体执行真实世界任务的运行时」**，并提供 **100 元免费额度（90 天有效）** 的获客钩子。

### 2.2 供给侧：IDC 闲时 GPU 是被低估的「沉睡资产」

- 国内大量 IDC 与智算中心完成 GPU 上架后，受客户结构、批次交付节奏、业务周期影响，**日均利用率往往无法打满**。
- 闲时时段的电力、机位、运维成本是刚性支出，**闲置 = 净亏损**。
- 传统 IDC 缺乏三样东西：**标准化的算力产品**（不会把裸机变成可售卖的卡时）、**计量与计费系统**（不知道卖了多少、该收多少）、**客户通道**（没有面向开发者的分销能力）。

> 这正是本平台的三位一体价值：**产品化 + 计量化 + 分销化**。

### 2.3 竞对标的市场验证

平台对标的产品形态已在全球被验证：


| 对标                              | 模式                                     | 对我们的启示                            |
| ------------------------------- | -------------------------------------- | --------------------------------- |
| **Novita**                      | Serverless 推理 + GPU 实例 + Sandbox，开发者友好 |  |
| **Lambda / CoreWeave / Crusoe** | 专注 AI 的 GPU 云                          | 证明「非超大厂 GPU 云」有独立生存空间             |
| **AWS / Azure Spot**            | 抢占式实例市场                                | 证明 Spot 是行业标配的闲时变现通道              |
| **国内算力交易平台（如算力.cn 生态）**         | 算力撮合与开放 API                            | 我们已通过 OpenAPI 完成深度对接，当前是其生态运营方    |


### 2.4 市场规模判断（框架）

- **TAM**：中国 AI 算力服务市场（训练 + 推理卡时），千亿级人民币量级，随大模型部署与 Agent 普及持续扩张。
- **SAM**：闲时 / 弹性 / 抢占式 GPU 细分——本质是「非独占、可回收、按量计费」的那部分卡时，通常可占到整体 GPU 消费的 **30%–50%**（**测算区间 · 数据出处待补**）。
- **SOM**：通过已接入的 IDC 资源池 + 分销商户网络，未来 12 个月可锁定的卡时吞吐（以实际接入卡数 × 目标利用率测算，见 §9）。

### 3.3 三层定价体系（平台的核心定价基础设施）


| 层级     | 名称          | 用途            | 说明                         |
| ------ | ----------- | ------------- | -------------------------- |
| **L1** | 平台刊例价       | 平台向租户的销售价      | `机房 × 卡型 × 产品线 × 计费单位`；机房设备配置（卡型 / 内存 / 数据盘）不同则刊例价不同——**机房级是 L1 的内部子维度**，不是独立一层 |
| **L2** | 机房成本价       | 平台向 IDC 的采购成本  | 按合作模式（租赁 / 分成 / 自建）不同而不同；**仅作毛利核算底座，不参与对外计费**（租户按 L1、商户按 L3/L4 计费） |

### 3.4 供给侧产品（供应商生命周期管理）

我们的供给侧不是「资源登记表」，而是一套完整的**资源资产管理系统**：

- **看得见**：供应商 → 机房 → 卡型 → 单机四级下钻；全局限量与生命周期漏斗（待接入 / 在线 / 异常 / 退役）。
- **接得进**：批量接入批次 + 施工任务 + 实体状态变更全链路审计（`entity_state_transition_log`）。
- **管得住**：设备平台探活（k8s / proxy / 裸金属三通道对账）、故障事件（`faultIncident`）、整租设备管理。
- **算得清**：供应商合同、单价成本（`supplierUnitCost`）、裸金属订单、平台刊例价与机房级刊例价快照。
- **追得到**：**机房 SLA 考核**——故障次数、资源利用率、故障卡时、闲置率、浪费率、上架损耗，按机房 × 卡型 × 自然日核算，P0 支持单设备 SLA 与**算力券赔付**。

### 3.5 商户与渠道（分销体系）

- 商户模型内置 **OEM（Self-Host）品牌独立站 / IFrame / Promo 推广链接 三种接入模式**，默认直营商户 + 分销合作伙伴商户并存。
- 覆盖商户进货价、商户充值、商户账单（日/月 rollup）、商户区域与卡型价目、商户租户管理。
- **销售 SOP 已标准化**：接触客户 → 发算力券 → 线下充值 → 折扣申请 → 裸金属开通，全程飞书工单流转。
- **提成激励机制已落地**（`docs/business/cost.md` v1.3，执行期 2026-05-01 \~ 2026-12-31）：提成 = 当月毛利基数 × 提点比例，按「商机来源 × 客群（新客 / 老客）× 受益角色」三维查表（2026-10-06 起实现维度由「成交后月序」改为「客群」，提点数值不变）；销售自拓最高 15%，市场来源 10%（新客）→ 7%（老客）——**用销售杠杆撬动供给与需求两侧增长**。

### 3.6 Agent Sandbox：独家技术 —— 为「执行不可信 AI 代码」而生的运行时

> **这是我们区别于所有「通用容器方案」的独家技术内核。** 市面上绝大多数算力平台把「运行负载」交给通用容器（如 Docker 类），本平台则内置一套**专门为 AI 智能体（Agent）与基于 Agent 的训练（RL）而设计**的执行运行时——Agent Sandbox。

**它解决什么样的问题：**

AI 智能体在完成任务时不只是「推理」，而是要「动手执行」：运行模型生成的代码、调用工具、操作浏览器、读写中间结果、连续多步试错（编码 → 数据分析 → RL 训练）。这些负载有三个传统平台完全不适应的特征：

1. **代码不可信**：执行的是模型当场生成的、未经审计的任意代码——传统容器把「信任」假定为镜像可信，而 Agent 场景的默认假设必须是「**零信任**」。
2. **生命周期极短、并发极高**：一次 Agent 任务可以分钟级打开 / 销毁成百上千个执行环境，传统容器是给「长驻服务」设计的，环境启停开销大、配额与计量粗糙。
3. **潮汐与可中断**：Agent 任务是典型的「尖峰脉冲式」负载——这正是**闲时算力最理想的需求侧**：愿意牺牲稳定性换取低价。

**Agent Sandbox 与传统容器方案的本质差异：**


| 维度   | 传统容器方案（Docker 类）      | 我们的 Agent Sandbox                                           |
| ---- | --------------------- | ----------------------------------------------------------- |
| 设计初衷 | 打包 / 部署**长期运行的业务服务**  | 执行**短生命周期的不可信 AI 生成代码**                                     |
| 信任模型 | 信任镜像与部署者，安全靠「配置」      | **默认零信任**，面向任意代码设计隔离与边界                                     |
| 生命周期 | 分钟级启停、长驻运行            | **秒级创建/销毁**、用完即焚、池化复用                                       |
| 并发形态 | 适合少量长活进程              | 从 1 个到**数千个**并发的潮汐负载                                        |
| 编程接口 | 面向运维（SSH / 编排 / 镜像管理） | **面向程序**：`create → run_code → kill` 三步 API                  |
| 有状态  | 持久盘为主，快照/回放弱          | 面向 RL 训练的**环境速建 / 复用 / 重置**                                 |
| 配额治理 | 资源规格为主                | **并发数 / 最大存活时长 / 存储 / 算力**多维配额与分级（Free / Paid / Enterprise） |
| 计量计费 | 按容器时长 / 机器粒度          | **按调用 / 按秒**与平台计费引擎一体                                       |
| 成本定位 | 贵、重、面向工程师             | 轻、便宜、**面向 Agent 的每一次行动**                                    |


**为什么这是独家技术：**

1. **不只是「沙箱技术」，而是「算力 × Agent 的适配层」**——它把「闲时 GPU 调度 + 秒级计量计费 + 不可信代码执行」做成了同一套运行时的三个面。竞争对手要么有算力没有 Agent 运行时，要么只做 API 不碰算力调度，**没人同时拥有这两条腿**。
2. **入口就是商业模式**：Agent Sandbox 以 **SDK / API** 形态暴露（`pip install` + 三行代码即可拥有一个隔离执行环境），对象是「每个 Agent 的每一次行动」，而不是「每个租户的一台机器」——**把算力消费颗粒度从「台」细到「次」**，用量与收入随 Agent 生态自然放大。
3. **配套产品已齐备**：沙箱市场（模板复用 / 私有模板）、配额分级（Free 拉新 → Paid 转化 → Enterprise 定制）、用量与成本分析、与统一账单一体——**不是单点 demo，是一套能直接变现的产品闭环**（当前为高保真 UED，后端纳入本轮融资落地范围）。

**对投资人的意义：**

- 乘上 **Agent 经济**（AI 智能体爆发）与 **RL 训练**（强化学习对海量执行环境的需求）两条最陡峭的增长曲线；
- 天然是**闲时算力的「填谷型」完美客户**（可中断、潮汐、价格敏感），与 §3.1 供给侧逻辑互为因果、互相增强；
- 是差异化定位中除了「算力转售」之外、**最难被模仿的第二增长曲线**。

### 4.3 单位经济模型（Unit Economics，示意）

以一张 **H100 80GB** 为例的卡时经济学（示意，实际以 L2 机房成本价核算）：

```
假设某机房 H100 闲时采购成本   ≈ 1.10 元/卡时（L2 成本价）
平台刊例按量价（L1）            = 2.59 元/卡时
Spot 零售价                    = 1.55 元/卡时

毛利/卡时：
  按量路径   2.59 − 1.10 = 1.49 元  （毛利率 ≈ 57%）
  Spot 路径  1.55 − 1.10 = 0.45 元  （毛利率 ≈ 29%）
  但 Spot 把「0 收入的闲置卡时」变成收入 → 对 IDC 是纯增量

平台运营成本分摊（人力/云资源/支付通道/销售提成）：
  按毛利 × 提点矩阵计提（销售 7%~15% + 部门池 3%~9%——市场/销售来源为 6%~9%，见 docs/business/cost.md）
```

**关键结论**：

1. **Spot 是「填谷」产品**——牺牲单价换取利用率，把沉睡资产变现，是对 IDC 最有说服力的合作理由。
2. **按量/裸金属是「利润」产品**——贡献高毛利与稳定现金流。
3. **渠道是「杠杆」**——OEM 商户自带客户，平台让渡部分差换取零边际获客成本。
4. **Agent Sandbox 是第二条高毛利曲线**——按调用/按秒、颗粒度极细，随 Agent 生态放量增速最快（详见 §3.6 / R5b）。

### 5.3 我们的护城河（Moat）

1. **供给侧合约与数据壁垒**：机房接入批次、合同、报价白名单、成本单价、SLA 考核历史——这些是多年运营沉淀、不可速成的数据资产。
2. **计量计费的准确性 = 信任**：秒级计量、5 分钟出账、三层防超额、财务月结与提成派生——算力生意的本质是「算得清才敢大规模做」。
3. **定价引擎的三层结构**：同一卡型在不同产品线、不同机房、不同商户下独立定价，支撑复杂商务博弈，竞对难以快速复制。
4. **渠道与销售组织**：OEM/IFrame/Promo 三种接入 + 飞书工单化 SOP + 毛利提成矩阵，形成可复制的地面部队。
5. **调度引擎自建后**：从「依赖外部算力平台的转售商」升级为「自有调度的算力 OS」，摆脱通道依赖、打开毛利与定价自主权。
6. **Agent Sandbox（独家技术）**：把「闲时调度 × 秒级计量 × 不可信 AI 代码执行」放在同一体系内——竞对要么有算力没有 Agent 运行时，要么只做 API 不碰算力，**目前尚未见同时布局两端的同类方案**，详见 §3.6。

## 8. 增长战略与里程碑

### 8.1 三阶段路线图

#### Phase 1（0–6 个月）：**「接得进、算得清」——供给侧扩张 + 自建调度 MVP**

- 落地 SkyPilot + Kueue + Volcano 调度栈，完成 **3–5 个 IDC 边缘集群**接入与统一控制面。
- OpenMeter 秒级计量与 5 分钟出账上线，三层防超额投产。
- Node Agent 同时支持 K8s/K3s 与裸金属双模式，存量机房平滑接入。
- 消费者端交易后端打通：注册 → 充值 → 下单 → 计量 → 出账全链路。
- SLA 考核模块正式上线，形成对 IDC 的议价与汰换依据。

**目标**：在线卡数翻倍，Spot 填谷收入占比 ≥ 30%。

#### Phase 2（6–18 个月）：**「卖得出、粘得住」— 需求侧规模化 + 渠道杠杆**

- **Agent Sandbox 全面上线**：SDK/API 化执行运行时落地，Free/Paid/Enterprise 配额分级，对接 RL 训练与 Agent 标杆客户。
- Serverless 推理端点全量开放，接入 Agent / AIGC 标杆客户。
- OEM / IFrame / Promo 商户网络扩张，提成矩阵驱动的地推复制。
- 应用商店与镜像预热商业化：预热点计费 + 社区镜像 Revenue Share。
- 镜像加速、S3 存储卷等增值产品线齐备。
- 建立客户成功与技术支持体系，SLA 赔付机制建立信任背书。

**目标**：付费租户数量级增长，Top10 客户集中度下降（健康度指标），毛利率稳定在设计区间，**Agent Sandbox 成为第二增长曲线**。

#### Phase 3（18–36 个月）：**「调度自主 + 生态化」——算力操作系统**

- 自研调度器演进：多 IDC 联邦调度、竞价与优先级混合策略、忙闲时动态定价。
- 算力开放 API 与 Agent Skills 生态：让 AI 智能体直接「购买并使用」算力——Agent Sandbox 成为 Agent 生态的默认运行时。
- 供给侧金融化探索：基于稳定卡时现金流的供应商结算与供应链金融。
- 考虑区域扩展（海外节点）与合规资质（等保、算力交易平台资质）。

### 8.2 增长飞轮

```
更多 IDC 闲时资源 ──► 更低采购成本 / 更多卡型 ──► 更低零售价（Spot 6 折）
```

## 9. 财务模型（测算框架）

> **披露说明**：以下为基于平台已实现定价口径与提成政策的**测算框架与情景假设**，非承诺业绩。尽调阶段可提供线上系统实际流水与《运营月报》数据替换假设值。

### 9.1 关键假设


| 假设项                    | 悲观    | 基准    | 乐观    |
| ---------------------- | -----: | -----: | -----: |
| 12 个月后在线卡数（折算 H100 当量） | 500   | 1,500 | 4,000 |
| 平均利用率（含闲时填谷）           | 35%   | 50%   | 65%   |
| 综合零售均价（元/卡时，加权）        | 1.40  | 1.60  | 1.80  |
| 综合采购成本（元/卡时，加权 L2）     | 1.00  | 0.95  | 0.90  |
| 卡时毛利率                  | 28.6% | 40.6% | 50.0% |
| 销售/渠道提成（占毛利）           | 18%   | 15%   | 12%   |
| 运营与研发费用年增速             | 高     | 中     | 中     |


### 9.2 基准情景：卡时收入测算（示意）

```
年可用卡时   = 1,500 卡 × 8,760 小时 × 50% 利用率 ≈ 657 万卡时
年卡时收入   ≈ 657 万 × 1.60 元        ≈ 1,051 万元
年采购成本   ≈ 657 万 × 0.95 元        ≈  624 万元
毛利         ≈                          427 万元（毛利率 40.6%）
减：销售提成（15% of 毛利）             ≈   64 万元
减：平台运营（研发/云资源/支付/人力）     视团队规模
裸金属 / 商户批发 / 增值收入             另计（R2/R3/R5）
```

### 9.3 收入结构演进预期


| 阶段      | R1 转售价差 | R2 裸金属 | R3 渠道批发 | R4/R5b Serverless+Sandbox | R5 生态增值 |
| ------- | -------: | ------: | -------: | -------------------------: | -------: |
| Phase 1 | 65%     | 20%    | 5%      | 6%                        | 4%      |
| Phase 2 | 50%     | 20%    | 12%     | 12%                       | 6%      |
| Phase 3 | 40%     | 18%    | 15%     | 18%                       | 9%      |


*（R1 占比下降 = 收入来源多元化 = 抗风险能力增强；**Serverless + Agent Sandbox 合计为增长最快的组合**）*

### 9.4 盈利改善的四个杠杆

1. **利用率杠杆**：Spot 填谷让闲置卡时（0 收入）产生收入，直接抬升分母效率。
2. **采购议价杠杆**：卡时规模 ↑ → 对 IDC 的采购单价 ↓（L2 下探）→ 毛利率结构性提升。
3. **自建调度杠杆**：摆脱外部通道的通道费/加价，L2 成本进一步下移，且定价自主。
4. **Agent 生态杠杆（独家）**：Agent Sandbox 按调用/按秒计费、颗粒度极细，随 Agent 生态放量收入与毛利率增速最快，为平台打开「非转售」的第二条高毛利曲线。
