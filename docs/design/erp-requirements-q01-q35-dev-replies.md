### 0.1 当前阶段边界（务必先读）

### 0.2 答复三类标签

- **【已定/已实现（设计或原型）】**：仓库内已有明确设计或可点击的 console 原型行为。  
- **【设计已定、代码待接】**：schema/UED/API 文档已写清，正式服务/DB/平台联调尚未接。  
- **【需人工确认】**：运营 / 财务 / 老板 / 运维需拍板；下文用 **🔴 需人工确认** 标出，并尽量给选择题。

状态列取值：`已定` · `部分落地` · `未做` · `需人工确认`（可组合，以主状态为准）。

### 0.3 禁止误解

- 本答复**不编造**「已接真实 Lazada/Daraz 生产 API」「已上线审批引擎」「已完成物理库一库位一 SKU 唯一约束落地」等能力。  
- 「原型可点」≠「生产可用」。

## 1. 逐条答复 Q01–Q35

### Q01 · 系统架构（多平台 / 多国家 / 多店铺 / 多仓库 / 多币种）

- **问题摘要**：是否按多平台、多国家、多店铺、多仓库、多币种设计？  
- **运营最低要求**：新增平台或店铺时只增加配置与映射，不重做商品和库存结构。  
- **开发答复**：  
  - Schema / 设计以 `organization` + `shops`（`platform` ∈ daraz/lazada/shopee/tiktok_shop）+ 仓库编码 + `fx_rates` 配置化为目标；商品/库存按 **内部 SKU（variant）** 与仓位维度，不按平台拆表。  
  - **Daraz LK 与 Lazada 分池**（#33 / `daraz-lk-erp-p0-ued.md`）：Daraz = 海运→Colombo 本地仓；Lazada 五站可继续「厦门共享池」模型；**禁止**再写「Daraz 共用厦门现货池」。  
  - 控制台店铺连接、平台基础资料、汇率页均为配置面原型；扩展新站点 = 配置 + 映射，不重做 SPU/SKU/库存结构——**设计目标已定**，生产迁移未做。  
- **状态**：已定（设计） / 部分落地（原型配置壳）

### Q02 · Lazada 五国授权与 Token 续期

- **问题摘要**：五个国家站点如何分别授权，Token 如何续期？  
- **运营最低要求**：每个 Seller ID 独立监控授权状态，失效时提示。

  - Schema：`shops` + `integration_credentials` + `integration_states`（每店独立凭据/健康）；店铺页可展示连接态。  
  - **现状**：console 多为店铺壳 + 原型重授权；自动续期、失效告警 **待接** connector/worker。Marketplace 包支持 refresh 字段，默认 dry-run。

### Q06 · 订单去重与库存幂等

- **问题摘要**：同一订单重复同步如何避免重复生成和重复扣库存？  
- **运营最低要求**：接口必须幂等；重复数据不产生库存影响。  
- **开发答复**：  
  - Schema：`orders` 上 `uniqueIndex(shopId, externalOrderId)`；`pending_actions` 组织级幂等键唯一。  
  - 原型流水：`wms-store` / `order-store` 使用 `idempotencyKey`（如 `ledger:order_reserve:{extOrderId}:{sku}`），相同键直接返回已有流水、**不改余额**。  
  - 正式接入：同步 upsert + 库存事件幂等键；重放取消/扣减不得二次影响。  
- **状态**：已定（拟议） / 部分落地（原型幂等）
