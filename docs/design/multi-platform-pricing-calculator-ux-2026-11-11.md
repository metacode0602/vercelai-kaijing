# 多平台定价建议：最少操作方案与线框

- 日期：2026-11-11（Asia/Shanghai）
- 范围：apps/shop 定价建议计算器（实施合同；第一期按本文落地）
- 基线：open-shop `develop` `94cdea0`
- 前提：客户 HTML 中的数据与数字仅作演示，不作为验收线。
- 状态：字段与相关表结论已写入本文 §12；按 §11 建议默认及 §12 口径实施第一期。本文是实现合同。

---

## 1. 结论

只要每个产品或 SKU 把计税和费用数据定义完整，系统就可以按公式自动算出定价建议。多个平台时，先给出**所在平台**的主建议价，再并行给出**其他已配置平台**的对照建议，各用各的费率、税则和目标毛利，互不套用。

为减少操作，不把这件事拆成「先去费用模板、再去汇率、再去柜次、再去计算器」的多页流程，而是做成一个**定价计算器**：打开后自动从主档和平台配置带出数据，用户通常只需选 SKU（从详情进入则可省略）并确认平台与站点，即可看到建议价。缺什么只在本页列出，点一项补一项，补完自动重算。部分数据从平台侧配置或已同步的主数据获取，不要求用户手工抄费率。

本文件给出优化原则、数据来源、推荐路径、线框和分期实现建议，本文已作为第一期实施口径。

---

## 2. 设计目标

1. **最少操作**：从商品或 SKU 详情进入时，默认 0 次录入即可出建议；独立入口最多「选 SKU + 确认平台/站点」两步。
2. **能带出的一律带出**：采购价、箱规、毛重、HS、柜次海运分摊、汇率、平台佣金/回款/仓杂/包邮规则、目标毛利，优先读已有主档和费用模板，禁止同一数据多处重复填写。
3. **缺项可见、不假装完整**：缺税率、毛重、费用模板或汇率时，给出估算并标明缺项，不静默用默认税率，也不假装已经可以上架。
4. **一次看多平台**：本平台主建议始终在最前；其他平台用同一套成本（或该站点履约下的到仓成本）和各自费率再算一版，便于比较。
5. **演示数字不作验收**：公式和界面以可配置规则为准，不以讲义中的示例售价为对拍标准。

## 3. 现状痛点（为何要收成一个计算器）

当前成本与定价相关能力分散在多处，功能骨架已有，但用户要凑齐一次测算，需要自己串页：

| 页面 | 已有能力 | 对定价的不便 |
|---|---|---|
| `/console/costs` 与成本计算器工作台 | 本地测算、税栈/海运/建议价函数 | 大量字段需手填或重复确认，筛选与主档未自动带全 |
| `/console/ocean-containers` | 整柜成本、可写入 `sku_costs` | 分摊结果不会自动出现在「当前 SKU 的建议价」里 |
| `/console/fee-templates` | 已区分 Lazada / Daraz 等平台费率 | 模板粗（如服装/3C/家居），计算器不会按 SKU 品类自动选用 |
| `/settings/fx-rates` | 组织汇率 | 要另开一页查看，计算器未默认采用最新有效汇率 |
| `/console/compliance-hs-slsi` | HS/SLSI 建档与阻断 | 税则不会按 HS 自动代入税栈 |
| 商品 / SKU 主档 | 采购、箱规、重量等可维护 | 与计算器双向不通，用户容易漏填却不知情 |

结果是：数据其实可能已经在库里，但用户仍要记该去哪一页找，也难以一次看到「这个 SKU 在 Daraz 斯里兰卡卖多少、在其他站点建议卖多少」。

## 4. 最少操作原则

1. **入口跟着工作走**：在 SKU 详情、刊登编辑、整柜成本保存后，都提供「看定价建议」，不要只能从工具页找。
2. **默认即当前上下文**：从某店铺或某刊登进入时，平台、站点、店铺自动带入；目标毛利默认用该平台费用模板或组织默认值，可改但不必每次填。
3. **主档是唯一录入处**：箱规、毛重、HS、采购价只在商品/SKU（及柜次、费用模板）维护；计算器只引用，不另建一套平行表单。
4. **缺项就在结果上方**：用一条「已齐 x / 应齐 y」和可点击的缺项列表，点开后在抽屉或本页补，补的是主档本身，保存后立即重算。
5. **平台数据能拉则拉、不能拉则配置一次复用**：佣金、回款、仓杂、包邮上限等，优先读该租户已配置的费用模板；模板可由平台目录拷贝或后续对接官方费率，不让每个 SKU 再录一遍。
6. **算完可带走、默认不发布**：支持复制建议价、保存为「定价建议草稿」。不自动改线上刊登价，也不假装已向平台回写。

## 5. 数据从哪里来

计算器本身尽量只做「选对象 + 展示结果」。下表区分自动带出、平台/组织配置一次、以及必须按 SKU 补全的项。

| 数据 | 来源 | 用户日常是否需要再填 |
|---|---|---|
| 采购价、币种 | SKU / 最近采购或 `sku_costs` | 否，已维护则带出 |
| 箱规（外箱体积、每箱件数） | SKU 包装规格 | 否 |
| 单件体积 | 箱体积 ÷ 每箱件数，自动算 | 否 |
| 毛重（计从量税、柜重） | SKU 毛重 | 未维护时需补一次 |
| HS 编码 | SKU 合规档 / 品类建议，需人工确认 | 未绑定时需选一次，禁止静默「按品名猜中」 |
| 关税税栈（GD、附加、PAL、CESS、从量、消费税、VAT、SSCL 等） | 按 HS + 目的国 + 公式版本读取税率表 | 否，缺税则时标缺项 |
| 整柜海运费与单件分摊 | 该 SKU 所属柜次；按实际总 CBM 分摊（不是固定柜容） | 已做柜次成本则带出；无柜次时可改用最新运价卡做估算并标明 |
| 保险、本地费 | 费用模板或柜次实际发生 | 否 |
| 汇率 | 组织 `fx_rates` 当前有效汇率 | 否，缺汇率时标缺项，不写死演示汇率 |
| 佣金、回款、仓杂、包邮佣金及上限 | 该平台 + 站点 + 品类（或费用模板匹配规则） | 模板配好后否；无匹配模板时标缺项 |
| 目标毛利率 | 费用模板或组织/品类默认 | 可改，不必每次填 |
| 目的国、履约方式 | 当前店铺站点；多平台对照时用各站点自己的规则 | 否 |

「从平台获取」在本方案中分两层，避免把尚未对接的官方接口说成已经能拉：

- **现在就能用的**：租户已有的费用模板、平台目录拷贝来的模板名称与结构、组织汇率、SKU 主档、柜次写入的 `sku_costs`、已维护的 HS/税则。
- **后续可接的**：若某平台提供官方费率或类目佣金接口，再做成「从平台同步到费用模板」，计算器仍然只读模板，不在每个 SKU 上抓一次接口。未接通前，界面写清「来自本组织费用模板」，不显示成「已从平台实时同步」。

## 6. 推荐使用路径

用户不必理解公式细节。标准路径如下。

```mermaid
flowchart LR
  A[SKU 详情 / 刊登 / 独立入口] --> B[自动带出成本与费率]
  B --> C{必填项是否齐全}
  C -->|齐| D[出本平台建议价]
  C -->|缺| E[本页列出缺项并补全]
  E --> B
  D --> F[同时列出其他平台对照]
  F --> G[复制或保存建议草稿]
```

### 6.1 三种入口，同一计算器

1. **SKU / 商品详情**（主推荐）：标题区「定价建议」。进入后 SKU 已锁定，平台/站点默认为该 SKU 已绑定或最近刊登的店铺。
2. **刊登编辑**：在售价旁提供「按成本估算」。带出当前刊登的平台与站点，建议价可一键填入草稿，需用户确认才保存刊登，不自动发布。
3. **独立页**（建议升级现有成本计算器，而不是再做一个平行工具）：适合一次查多个 SKU，或还没有从详情进来的运营。路径可沿用 `/console/costs` 下的工作台，或收成「定价建议」子页，左侧菜单尽量不新增顶层项。

### 6.2 日常只需两步

1. 打开计算器（从详情进来则 SKU 已选；否则搜索选择一个 SKU）。
2. 确认平台与站点（默认当前，可改）、如需可改目标毛利。

页面立即给出：本平台建议零售价、包邮建议价（若该平台有包邮规则）、到仓/含税成本摘要、毛利是否达标，以及一个其他平台对照表。

### 6.3 遇到缺项时

不跳走、不弹复杂向导。结果区上方出现缺项条，例如「缺毛重、缺 Daraz 仓杂费率」。点击某一项：

- 毛重、箱规、HS：右侧抽屉编辑该 SKU 主档字段，保存写回主档并重算。
- 费用模板缺失：提示「该平台/站点还没有匹配的费用模板」，提供「去配置」深链到费用模板（配置一次，后续同类 SKU 复用），或允许临时用手动费率仅对本次测算生效并醒目标记「临时费率，未写入模板」。
- 无柜次成本：允许改用运价卡估算海运，结果标记「估算，非本柜实际分摊」。

## 8. 计算器功能规格

### 8.1 自动完成的事

- 按 SKU 装载采购、箱规、毛重、HS、最近 `sku_costs`、所属柜次分摊。
- 按所选平台 + 站点匹配费用模板与目标毛利默认值。
- 读取组织有效汇率，把成本币种与平台结算币种对齐；缺汇率则标缺项，不做演示汇率假换算。
- 按公式版本计算税栈、到仓成本、倒推零售价与包邮价。
- 对其它已配置且已有费用模板的平台/站点各算一行对照。
- 记录每一步的数据来源，便于审计。

### 8.2 用户可改、但不是必填

- 平台、站点、店铺。
- 目标毛利率。
- 公式版本（若组织同时保留旧税栈，仅作对照）。
- 临时费率（仅本次，明确标记）。
- 无柜次时改用运价卡估算。

### 8.3 明确不做（本阶段）

- 不自动向平台发布或改价。
- 不把 HTML 静态税则写死在代码里；税则进可维护目录，只对演示组织预置草稿，不自动推到已有租户。
- 不静默按品名匹配 HS 并直接计税。
- 不把跨币种金额加总成一个「总建议」。
- 不在未接通官方费率接口时，显示「已从平台实时获取佣金」。

### 8.4 结果如何带走

- 复制建议价。
- 保存为该 SKU + 平台 + 站点的定价建议草稿（可选，确认实现时再落表）。
- 从刊登页「填入建议价」只改本地草稿字段，保存刊登仍走现有流程。

## 9. 与现有模块的关系

建议**升级现有成本计算器工作台**为「定价建议」主界面，而不是再做一套互不通信的新页。费用模板、汇率、柜次、HS、运价卡仍是配置与事实来源，计算器是唯一日常消费面。

计算引擎应抽成可复用纯函数（设计中曾规划 `packages/freight`，也可放在 shop 内的共享计算模块），页面、刊登旁路、柜次保存后的批量列表都调用同一套，避免两套口径。税栈以版本号区分（例如新口径 `lk_cascade_v1` 与旧口径并存），默认用组织选定版本。

左侧菜单尽量不动：可在现有「成本」或财务相关分组下改名称/副标题，不新增第三个入口让用户猜该用哪一个。

## 10. 分期实现建议（第一期按此编码）

**第一期（即可用的最小闭环）**

- 统一计算引擎：到仓成本 + 倒推建议价 + 包邮两步回算；公式可版本化。
- 计算器主界面（线框 B）+ 缺项条与抽屉（线框 C）。
- 从 SKU 详情进入（线框 A），自动带出主档、`sku_costs`、费用模板、汇率。
- 本平台主建议 + 其他已配置平台对照（线框 B 右栏）。
- 明细可展开（线框 D）。缺项只给估算并标记。

**第二期（减少往返）**

- 刊登页填入建议价（线框 E）。
- 柜次 `ocean.saveCost` 之后的 SKU 列表接力（线框 F）。
- 费用模板按类目/HS 更精细匹配，减少「无匹配模板」。
- 定价建议草稿的保存与历史。

**第三期（更多「从平台获取」）**

- 在官方费率/类目佣金接口可用时，同步到费用模板，再被计算器引用。
- 其他目的国税则按同一引擎扩展，不复制一套 Daraz 专用页面。

权限相关功能按既有约定仍放到最后；本功能对当前组织成员开放即可。平台写操作（刊登发布、改价回写）本阶段不做。

## 11. 建议默认（供确认）

若按最少操作落地，建议采用以下默认，确认后再编码：

1. 主入口在 SKU 详情，独立工具升级现有成本计算器，不新开顶层菜单。
2. 打开即算；缺项显示估算并标「估算」，不阻塞查看，但保存到刊登草稿时需再次确认缺项。
3. 其他平台对照只列出「本组织已配置费用模板、且该 SKU 能给出到仓成本」的站点；配不齐的行显示缺项，不算假价格。
4. 费用与税率来自组织配置（含从平台目录拷贝的模板），第一期不接官方实时费率接口；界面如实说明来源。
5. 税则与演示数据不自动推送到已有租户；HTML 数字只作说明，不写进验收。
6. 建议价默认不回写刊登、不发布到平台；「填入建议价」必须用户点一次。

以上默认已作为实施口径，不再单独确认。

## 12. 数据模型：商品 / SKU 与相关表

结论：**不必在商品或 SKU 上堆扩展字段。** 税率、佣金、仓杂、汇率、目标毛利和建议价都不要写到 SKU，这些会随平台、站点和税则变化，应继续放在各自主档里供计算器引用。商品主档只补「箱规绑定」（以及可选的品类外键）；真正要新增或增强的是相关表。

对照基线 `develop` `94cdea0` 的 `packages/db/src/commerce-schema.ts`。

### 12.1 现有字段，够用、不再重复建

| 数据 | 已有位置 | 说明 |
|---|---|---|
| HS 编码 | `products.hs_code`，`product_variants.hs_code`（空则沿用 SPU） | 未填则计税标缺项，禁止静默按品名匹配 |
| 单件尺寸 | SPU / SKU 的 `length_mm` / `width_mm` / `height_mm` | 计件体积仍以箱规为准，单件尺寸不作外箱替代 |
| 重量 | SPU / SKU 的 `weight_grams` | 实施时明确为**净重**；从量税用的单件毛重由箱规毛重 ÷ 每箱件数得出，不必再加一套重量字段 |
| 采购价、币种 | `supplier_skus.unit_price` / `currency`（优先 `preferred`） | 不把采购价再抄一份到 SKU |
| 箱规库 | `commerce_carton_specs`（外箱长宽高、每箱件数、箱毛重） | 主档已够用，缺的是和 SKU 的绑定 |
| 柜次分摊结果 | `sku_costs`（含柜次、税费拆分、模板版本、汇率、到仓成本） | 计算器优先读最近有效版本 |
| 汇率 | `fx_rates` | 缺有效汇率则标缺项，不写死演示汇率 |
| 平台费率骨架 | `fee_templates` + `fee_template_versions`（已有平台、国家、`components`、`formula_profile`） | 缺的是按 SKU 类目 / HS 自动匹配 |
| 刊登正式售价 | `listings.price_amount` / `price_currency` | 第一期不把建议价写回此字段 |

不要把费率或税则塞进 `products.payload` 或 `product_variants.attrs` 当作正式字段。

### 12.2 商品 / SKU：只补绑定，不堆计价字段

1. **`product_variants.carton_spec_id`（建议实施）**  
   可空外键，指向同组织 `commerce_carton_specs.id`。这是自动算出件体积、箱数和单件毛重的关键。抽屉里补箱规时写回该绑定，而不是在计算器里另存一份尺寸。

2. **`products.category_id`（建议实施）**  
   可空外键，指向 `commerce_categories.id`。商品目前只有 `category_hint` 文本，无法稳定匹配费用模板。这不是计价扩展字段，而是主档与模板之间的关联。

3. **不新增的 SKU 字段**  
   不含税率、佣金、仓杂、包邮规则、汇率、目标毛利、建议售价。也不为毛重再加并列字段（见上，单件毛重由箱规计算）。

### 12.3 相关表：需要新增或增强

1. **HS 税则新表（设计已有、尚未落地）**  
   现有 `compliance_hs_rules` 只有 SLSI 与建档/上架阻断，没有 GD、附加、PAL、CESS、从量、消费税、VAT、SSCL 等税率。按已有设计增加 `hs_tariff_versions`（或等价表），按 HS + 目的国 + 版本维护，不写进商品行。税则与演示数据不自动推送到已有租户；演示组织可预置草稿。

2. **费用模板增加匹配规则**  
   在模板头或独立规则表增加类目和/或 HS 匹配（及优先级）。`fee_templates` 已有平台、国家和费率明细，第一期不把官方实时接口做成「已同步」，界面如实写「来自本组织费用模板」。

3. **柜次行补箱数与 CBM**  
   `ocean_shipment_lines` 目前只有数量；体积在 `ocean_shipment_boxes` 上且箱子不绑定 SKU，不利于按「本件 CBM / 本柜实际总 CBM」分摊。在行上增加箱数、CBM（可按箱规和数量回填，允许人工修正）。分摊结果仍写入已有 `sku_costs`。

4. **定价建议草稿表（第二期，第一期不做）**  
   将来如需保存建议，单独做「SKU + 平台 + 站点 + 建议价 + 计算快照」表。不要改刊登上的正式售价，第一期只支持复制和现场查看。

5. **组织设置（可选，能省则省）**  
   默认目标毛利和默认公式版本可放在费用模板已有的 `formula_profile` 与模板默认毛利里；若确需组织级兜底，再给 `organization_settings` 加可选字段，不作为第一期必做。

`fx_rates`、`sku_costs`、`supplier_skus`、`commerce_carton_specs` 本身够用，第一期不为它们叠计价扩展列。

### 12.4 第一期实施口径（已作为默认，按此编码）

- 主入口在 SKU 详情；独立工具升级现有成本计算器，不新开顶层菜单。
- 打开即算；缺项显示估算并标「估算」，不阻塞查看；不自动改刊登价、不向平台发布。
- 其他平台对照只列出本组织已配置费用模板、且能给出到仓成本的站点；配不齐的行只标缺项，不算假价格。
- 税栈默认采用无 10% CIF 上浮的级联公式（`lk_cascade_v1`）；旧口径若保留仅作对照。讲义数字只作演示，不以示例售价为验收线。
- 倒推建议价分母按标准毛利公式，不用讲义中的 0.365 笔误。
- 海运优先用所属柜次按实际总 CBM 分摊；无柜次时可用运价卡估算并标明。
- 权限相关仍放到最后；本功能对当前组织成员开放。不改 OAuth / 店铺授权实现。
- 中文界面；真实写入数据库；不把 HTML 静态税则写死在 TypeScript 里。
