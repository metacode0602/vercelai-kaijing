# 好时运 ERP：P0/P1 页面 UED 补充设计

**状态：** 设计阶段 UED 规格，未接业务 API / 持久化。基础主数据 CRUD 首批页面见 [平台基础资料与基础字典 UED](./haoshiyun-platform-basics-ued.md)。本文补全附件中尚缺页面的 IA、主要状态、操作和页面关系，供后续逐页制作交互原型。

## 1. 总体 IA 与全局交互

```text
工作台
  经营总览 / 待办中心
基础资料
  店铺 / 平台站点 / 仓库与库位 / 商品 SPU / SKU / 属性字典 / 供应商 / Seller SKU 映射
采购与库存
  采购申请 / 采购审核 / 采购单 / 收货质检 / 库存查询 / 库存流水 / 库存调整
订单履约
  订单 / 映射异常 / 包裹与物流 / 售后
经营分析
  销售与库存报表 / 成本利润 / 结算费用
系统
  接口同步日志 / 操作审计 / 数据导入 / 角色权限
```

- 顶部固定当前组织与数据范围；菜单、列表、导出、详情均遵循同一权限 scope。
- 列表统一为数据库分页式 UED：筛选器→结果总数→列配置/导出→表格→页码。筛选项进入 URL；默认只显示高频筛选，更多条件折叠。
- 用“新增/保存/提交审核/审核通过/收货”等对象动作，不使用模糊的“处理”。状态 Badge 使用统一字典文案；失败显示下一步操作。
- 所有写操作均呈现保存范围、状态及操作者；演示阶段展示“示例数据 / 未连接”，不伪装真实接口状态。
- 详情页采取主信息 + 状态时间线 + 关联记录。侧栏展示相关对象数量和链接，避免同一信息重复录入。
- 共用动作：搜索、清空、导出、查看详情、复制业务编码。导出需权限；不因按钮隐藏而省略服务端权限校验。
- 侧栏按工作台、基础资料、采购库存、订单履约、经营分析、系统管理六组组织；当前项必须显示页面标题，避免模块扩展后出现平铺长菜单。

## 3. 基础资料页面

### 3.1 店铺列表、创建与编辑

**列表列：** 店铺名称/代码、平台、国家站点、Seller ID、负责人、履约模式、默认出库仓、关联仓库数、币种、授权/API 状态、最后同步时间、店铺状态。筛选平台、国家、负责人、授权状态、店铺状态；一行主操作“查看”，更多操作“编辑/暂停”。店铺编辑从设置→店铺连接进行。

**创建流程（单一向导，保留上下文）：**

1. 选平台；站点选项过滤为平台支持的 `Marketplace`，显示国家/站点名称及状态。
2. 选站点后自动带出币种、IANA 时区、默认履约模式；对可覆盖字段显示“来自站点默认值”。
3. 输入平台店铺名、Seller ID、平台账号标识（不录密码）、店铺组/主体/负责人；展示生成店铺代码预览，不让用户决定系统 ID。
4. 从当前组织启用仓库中多选一个或多个可选仓库。选项显示仓库名、代码、类型、国家和状态。
5. 在已选仓库中指定且只能指定一个“默认出库仓”。变更选择时如移除当前默认仓，必须先选另一默认仓；空仓列表时引导去创建仓库，不允许保存不完整店铺。
6. “更多设置”收纳库存模式/库存池、上线日期、平台特殊字段。保存草稿或创建；授权为后续明确动作，不把保存与 OAuth 混为同一操作。

**编辑规则：** 已关联订单的关键身份字段（platform、site、Seller ID）只读或走显式迁移流程；仓库关系编辑用多选清单，默认仓 Radio/单选；停用店铺不删除订单和映射。站点默认变化只影响新建店铺，不静默覆盖已保存设置。

### 3.2 仓库列表 / 仓库详情 / 库位

**列表列：** 仓库名、代码、类型、国家、时区、核算币种、关联店铺、库位数、启用状态、最后库存变动。详情 Tabs：仓库资料 / 关联店铺 / 库位 / 库存摘要 / 变更记录。

**库位管理：** 添加库位时可粘贴/批量导入编码；同仓库编码唯一。库位列表显示绑定 SKU、状态、占用量、最近盘点。绑定单个启用 SKU；一个库位不得绑定第二个有效 SKU。解绑/换绑需库存为零或先走库存转移单（执行前提待业务确认）；历史绑定作为记录保留。

### 3.3 SPU 商品与内部 SKU

- SPU 列表：SPU、名称、品牌/品类、状态、负责人、SKU 数、供应商数、Listing 数、更新时间；按名称/编码/字典/状态筛选。
- 新建 SPU：先填名称、品牌、品类、商品负责人；材质/款式按品类规则条件必填；系统生成 `HSYxxxxxx` 预览。保存后进入 SPU 详情。
- SPU 详情：商品资料 / SKU规格 / 供应商 / 平台刊登 / 变更历史。
- SKU 在 SPU 详情的规格矩阵创建：服装品类按颜色×尺码建立；用户可取消不存在的组合再批量生成。包装规格为组合辨识字段。系统生成 SPU+三位流水，不允许重用停用编号。提交前显示将创建的 SKU 行数和差异。
- SKU 详情展示颜色/尺码/包装、重量尺寸、条码、标准成本（标注 P1）、状态、供应商报价、各仓库存和 Seller SKU 引用。停用有引用时需解释影响，不物理删除。

### 3.4 供应商与 SKU 供应商关系

- 供应商列表支持名称/编码/联系人/状态搜索；详情维护联系人、联系方式、状态和历史变更。
- SKU 详情中新增供应来源：供应商、厂家款号、采购价/币种、生效日期、MOQ、交期、首选标记。供应商可重复关联不同 SKU；同一 SKU 的启用供应来源最多一个首选。
- 替换价格新增一条生效期记录，不覆盖已生成采购单上的历史价。供应商停用后不能新建采购申请，但历史单据继续显示。

### 3.5 Seller SKU 映射

- 映射列表默认按店铺筛选，列平台/站点/店铺、Item ID、平台 SKU ID、Seller SKU、内部 SKU、颜色尺码、上架状态、映射状态、最后同步。
- 新增可从 Listing 导入候选变体，也可人工添加。选择店铺后可搜索该店铺已知 Seller SKU；映射到一个启用内部 SKU。唯一冲突在保存前显示冲突记录并阻止保存。
- 批量导入支持预览、逐行校验、冲突下载；未确认映射保留“待确认”，订单在映射确认前进入异常且不占库存。

## 4. 采购页面与状态流

### 4.1 采购申请

列表 Tab：我的申请 / 全部可见 / 待我审核；列申请号、申请人、SKU、数量、供应商、金额、期望到货、仓库、状态、申请时间。申请人通过“新建申请”录入原因、SKU/数量、供应商、报价币种/单价、预计到货、收货仓库和备注；常用供应商/价格默认带出但允许按权限调整。明细可多行。

提交后只允许撤回尚未审核的申请；驳回后编辑并重新提交时保留旧审核历史。审核状态与采购单状态分开显示。

### 4.2 审核队列

审阅面板聚焦申请内容和差异：申请人、商品、数量、报价、供应商、仓库、历史申请/当前库存。底部仅有“通过”与“驳回”；驳回理由必填（建议规则，待确认）。申请人不得自审；杨洁申请由黄发聪审、黄发聪申请由杨洁审；普通员工由杨洁或黄发聪任一人审。提交前显示“由谁审核”，业务服务再校验。

### 4.3 采购单 / 收货质检

- 审核通过后从申请生成正式采购单；采购单号此时生成。列表显示已订/已收/待收/合格入库数量。
- “登记到货”按采购单行新增收货批次，可分批；记录数量、时间、操作人、供应商单据附件（附件能力后续确认）。
- 收货批次进入质检，逐 SKU 行录入合格/不合格/缺件数量及结果；数量合计不可超过本次收货数。
- “确认入库”要求指定仓库与库位，只将合格量形成库存流水；入库后展示流水号。部分收货/质检留在待完成状态，不要求整单一次结束。
- 无权限、草稿、未审核或已关闭单据的写操作展示锁定状态和原因。

## 5. 库存页面

### 5.1 库存查询

筛选组织可见仓库、库位、SPU/SKU、颜色尺码、库存状态；默认聚合按 SKU+仓库，展开后看库位。列：实际、预留/锁定、质损/不可售、可用、待入库、最近变化。可用量公式标注在列说明，不把多店铺库存重复相加。跨仓合计可展示，但不允许误把一个 SKU 多个库位当多个商品。

### 5.2 库存流水与调整

- 流水为只读追加表：时间、SKU、仓库/库位、类型、前值、变化、后值、来源单、操作者、原因；从余额可下钻到时间序列并按来源单追到采购/订单/售后。
- 调整从“创建调整单”开始，支持盘盈、盘亏、报损、库位转移；必须输入原因/来源。审核机制/阈值显示“业务规则待确认”，未确认前仅展示草稿提交，不伪造审批策略。
- 确认调整后产生不可编辑的流水；纠错创建反向调整，禁止编辑历史行。

## 6. 订单、包裹和履约

### 6.1 订单列表/详情

列表筛选日期、平台、国家、店铺、内部订单状态、付款/履约状态、Seller SKU/内部 SKU；列平台订单号、站点、下单时间、状态、SKU 行数、金额/币种、映射/库存异常标记。默认按下单时间倒序，数据库分页。

详情由订单摘要、商品行、库存处理、包裹轨迹、状态时间线组成。每条商品行显示原始 Seller SKU 与映射结果；保留平台原始状态及内部状态。重复同步不生成第二单。订单状态哪个节点锁库/正式扣减尚待 Q07 确认，UED 用“库存处理规则待确认”标签。现有订单详情已加此提示，并提供映射检查、履约与售后入口，但入口仅为原型导航。

### 6.2 映射异常

异常队列类型：未映射、重复映射、SKU停用、店铺停用/授权失效、字段校验失败。列表显示阻断原因及订单行数；操作“去映射”“重试识别”“查看原始数据”。映射问题解决后显式重试，系统记录处理人/时间；禁止异常单静默扣库。

### 6.3 包裹/物流

一订单多包裹。包裹详情有运单号、承运商、发货仓/库位、重量、关联订单行、事件时间线。站点履约模式决定流程展示：MY/PH/SG/VN 展示自营仓→LGS→签收；TH 展示自营仓→JSB交接→清关→Lazada官方尾程→签收。状态值从接口同步或手工批量导入，手工字段标来源。JSB API 能力未确认，先设计人工事件记录。

## 7. 售后、利润和费用

- 售后列表按申请时间、类型、状态、店铺搜索，列原订单、SKU、退款金额/币种、退货状态、处理状态。
- 售后详情事件：平台申请→退款确认→（如退货）仓库签收→质检→可售回库/残次/报废→完成。仅退款没有实物回库；取消按已确认库存节点释放预留。实际退货数量必须分配到质检结果，只有可售数量入可用库存。
- 费用详情以费用行呈现类型、金额、原币、币种、来源（平台/结算导入/JSB/物流/人工）、业务日期、导入批次、关联订单/包裹。利润字段在成本算法、汇率与分摊未确认前显示“待计算规则”，不能在 UED 把 mock 数值标成实际利润。

## 8. 仪表盘与报表

- 全局筛选：日期范围、平台、国家/站点、店铺、履约模式、负责人、本位币；可保存常用筛选。默认取权限允许范围，不自动扩大到全组织。
- 首页只放可行动指标：待发货、缺货/低库存、待审采购、退款处理、未映射订单、API 异常；销售额/毛利/净利等口径确认后再显示。
- 每项指标点击进入使用同筛选的明细列表；页面显示数据更新时刻、币种口径和完整性。多币种合计先明确汇率折算，否则分币种展示。
- 报表中心为销售、库存、采购、周转视图；任一汇总可下钻订单/SKU/仓库明细。导出只导出当前筛选结果并受权限控制。

## 9. 导入迁移、系统日志与权限

### 9.1 导入向导

步骤：选模板类型→下载模板→上传文件→字段映射→校验预览→确认导入→结果。预览按可导入/需确认/错误分类并列原文件行号、字段、原因、建议修复。错误行默认不影响正确行；迁移批次支持在无后续依赖时撤销，若已产生后续流水则通过补偿方式，不能物理删除历史。

模板优先：仓库/库位、商品/SKU、Seller SKU 映射、期初库存、历史订单。库存“无进货/未知/文本”不得静默转 0；由规则标注需确认。

### 9.2 接口与操作日志

接口任务列表显示店铺、类型、起止时间、成功/失败数、重试次数、状态和易读错误；详情提供脱敏请求摘要、平台响应摘要、游标/关联批次和“人工重试”。操作审计只读，筛选人/对象/动作/日期；详情按字段显示修改前后值、来源、request id。敏感凭证不展示。

### 9.3 角色权限

角色列表可按模块配置查看/新增/修改/审核/导出/配置权限；范围选择全组织、平台、站点或指定店铺。人员详情绑定角色和负责范围，并启用/停用。矩阵预置附件中的蔡值、杨洁、黄发聪、Lazada/Daraz运营、美工、运营助理、外部 IT 作为演示行；IT 技术排查不自动获得业务操作权。未经杨洁确认的矩阵标“待确认”。

## 10. 状态矩阵

| 页面 | 空状态 | 阻断状态 | 可恢复状态 |
|---|---|---|---|
| 店铺 | 先配置平台站点/添加店铺 | 平台或站点停用、授权未完成 | 编辑资料/执行授权 |
| 仓库/库位 | 添加仓库/库位 | SKU 已占用或仓库停用 | 创建转移/先解绑（规则确认后） |
| SKU 映射 | 导入/添加 Listing 变体 | 重复 Seller SKU、SKU 停用 | 去映射记录并重新确认 |
| 采购审核 | 无待审核 | 非审核人/申请人本人 | 转交规则待确认；不得自审 |
| 库存 | 尚无库存流水 | 无来源库存、并发预留不足 | 采购入库/审核调整/处理异常订单 |
| 订单 | 暂无订单或同步中 | 映射异常、授权失效 | 修映射/恢复连接/重试 |
| 导入 | 选择文件和模板 | 列缺失/重复键/数量非法 | 下载错误行、修复后新批次 |
| 报表 | 当前范围无数据 | 指标规则/汇率未确认 | 分币种展示或等待规则确认 |

## 11. 原型交付清单

后续逐页落地时按以下验收：

1. 店铺向导：平台→站点联动，选多个仓库、只在选中仓库中设唯一默认出库仓；移除默认仓要求先改默认。
2. 主数据：SPU/SKU、供应商映射、Listing 变体 Seller SKU 映射和冲突拦截。
3. 采购闭环：申请→PUR-001/2/3 审核→采购单→多批收货→分质检→合格入库。
4. 库存闭环：库存查询→订单预留/释放/出库→流水；无映射不影响库存；跨站点共用同仓库存。
5. 物流：LGS 与 TH/JSB 两种进度视图，人工事件与平台同步来源可辨。
6. 导入与权限：校验预览、行级错误、审计详情、scope 越权 blocked 状态。
7. 每页覆盖列表、详情、录入、成功、空、错误、阻断；显式标注示例数据。规则未确定项保持“待确认”。
