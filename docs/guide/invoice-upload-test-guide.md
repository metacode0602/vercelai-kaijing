# 发票文件上传功能测试指南

## 功能概述

运营人员在开具发票时，现在可以直接上传 PDF 或图片文件作为发票附件，而不是手动填写 PDF URL。

## 测试前准备

### 1. 环境变量配置

在 `apps/web/.env.local` 中添加（可选）：

```bash
# 发票附件存储目录（默认为 /tmp/invoice-attachments）
INVOICE_UPLOAD_DIR=/path/to/invoice-uploads
```

### 2. 确保存储目录可写

```bash
mkdir -p "${INVOICE_UPLOAD_DIR:-/tmp/invoice-attachments}"
chmod 755 "${INVOICE_UPLOAD_DIR:-/tmp/invoice-attachments}"
```

### 3. 启动开发服务器

```bash
pnpm run dev:web
```

## 测试步骤

### 1. 进入发票申请审核页面

1. 访问 `/supplier/invoice-requests`（运营人员登录）
2. 找到状态为 "已批准" 的发票申请
3. 点击 "开具发票" 按钮（文件上传图标）

### 2. 测试文件上传

#### 2.1 正常上传测试

1. 在 "发票附件" 区域点击 "选择文件" 按钮
2. 选择一个 PDF 文件（< 20MB）或图片文件（JPG/PNG/WEBP/GIF）
3. 验证：
   - ✅ 上传进度显示正常
   - ✅ 上传成功后显示文件名和大小
   - ✅ 根据文件类型显示正确的图标（PDF 或图片）
   - ✅ 显示 "上传成功" 提示

#### 2.2 文件格式验证测试

尝试上传以下文件格式：

| 格式 | 预期结果 |
|------|---------|
| PDF | ✅ 上传成功 |
| JPG/JPEG | ✅ 上传成功 |
| PNG | ✅ 上传成功 |
| WEBP | ✅ 上传成功 |
| GIF | ✅ 上传成功 |
| DOC/DOCX | ❌ 提示 "文件格式不支持" |
| TXT | ❌ 提示 "文件格式不支持" |
| ZIP | ❌ 提示 "文件格式不支持" |

#### 2.3 文件大小验证测试

| 文件大小 | 预期结果 |
|---------|---------|
| < 1MB | ✅ 上传成功 |
| 10MB | ✅ 上传成功 |
| 19MB | ✅ 上传成功 |
| > 20MB | ❌ 提示 "文件超过 20MB 限制" |

#### 2.4 文件删除和重新上传测试

1. 上传一个文件
2. 点击文件右侧的 "X" 删除按钮
3. 验证文件被移除，显示 "选择文件" 按钮
4. 重新上传另一个文件
5. 验证新文件正确显示

### 3. 测试发票开具流程

1. 填写所有必填字段：
   - 发票号码
   - 价税合计
   - 税额
   - 开票日期
   - **发票附件**（已上传文件）
2. 点击 "开具发票" 按钮
3. 验证：
   - ✅ 发票开具成功
   - ✅ 数据库 `invoice` 表中 `pdfUrl` 字段为文件访问路径（如 `/api/v1/invoice-files/2026-09/...`）
   - ✅ `pdfStorageKey` 字段为存储键（如 `2026-09/1234567890-abcdef123456.pdf`）

### 4. 测试文件访问

#### 4.1 通过浏览器直接访问

1. 复制开具发票后保存的 `pdfUrl`
2. 在浏览器中访问该 URL（如 `http://localhost:3000/api/v1/invoice-files/2026-09/1234567890-abcdef123456.pdf`）
3. 验证：
   - ✅ PDF 文件正常显示/下载
   - ✅ 图片文件正常显示
   - ✅ 响应头包含正确的 `Content-Type`

#### 4.2 查看已开具发票

1. 在发票申请列表中找到 "已开具" 状态的记录
2. 查看发票详情（如果有详情页面）
3. 验证：
   - ✅ 可以查看/下载发票附件
   - ✅ 附件链接正常工作

### 5. 测试错误处理

#### 5.1 未选择文件时提交

1. 不上传文件，直接填写其他字段并提交
2. 验证：❌ 提示 "发票号、金额、税额、开票日期和发票附件为必填项"

#### 5.2 网络错误模拟

1. 在开发者工具中模拟网络慢速/断开
2. 尝试上传文件
3. 验证：❌ 显示 "上传失败" 错误提示

#### 5.3 服务器错误模拟

1. 临时删除 `/tmp/invoice-attachments` 目录或移除写权限
2. 尝试上传文件
3. 验证：❌ 显示 "文件上传失败" 错误提示

## 验证数据库存储

连接数据库并查询已开具的发票：

```sql
SELECT 
  id,
  invoice_no,
  pdf_url,
  pdf_storage_key,
  issued_at
FROM invoice
WHERE issued_at > NOW() - INTERVAL '1 day'
ORDER BY issued_at DESC
LIMIT 10;
```

验证：
- `pdf_url` 格式为 `/api/v1/invoice-files/{YYYY-MM}/{timestamp}-{hash}.{ext}`
- `pdf_storage_key` 格式为 `{YYYY-MM}/{timestamp}-{hash}.{ext}`

## 验证文件系统存储

检查上传目录：

```bash
ls -lh "${INVOICE_UPLOAD_DIR:-/tmp/invoice-attachments}"
```

验证：
- 文件按 `YYYY-MM` 月份子目录组织
- 文件名格式为 `{timestamp}-{hash}.{ext}`
- 文件权限正常（可读）

## 性能测试（可选）

### 并发上传测试

使用多个浏览器标签页同时上传文件，验证：
- ✅ 所有上传都能成功
- ✅ 没有文件名冲突
- ✅ 响应时间合理（< 5s for 10MB 文件）

### 大量文件存储测试

上传大量文件后，验证：
- ✅ 文件系统空间充足
- ✅ 文件访问速度正常
- ✅ 可以考虑实施文件清理策略

## 已知限制

1. **存储方式**：当前使用本地文件系统存储，生产环境建议迁移到对象存储（S3/R2/OSS）
2. **文件清理**：没有自动清理未使用文件的机制
3. **权限控制**：文件访问 API 没有权限验证（可能需要根据业务需求添加）
4. **文件扫描**：没有病毒扫描或恶意文件检测
